① 整体形状：机制挂在流程的六个位置上

★ 这是本项目与上游最大的结构差异：判据不写在编排层里，而是挂在"流程位置"上。 位置是流程的形状（换实现不影响接线），判据是实现（可以一条一条换）。 编排层只调 registry.evaluate(point, ctx) —— 它不知道任何判据的名字。

② 机械判据：会真的开火的那 14 条

每条判据都必须三态裁决（ok / blocked / unmeasured）， 并自带三臂夹具（伪造臂 / 未测量臂 / 对照臂）。 requires 那一列是它的输入面 —— ★ 而"判据接进来了"与"它的输入接上了"是两件事， 本项目为此踩过五次，所以它单列一列。

契约 contract · 3 条

contract.build-artifact-scope 1 个输入 按 kind 适用

inScope 声明了 src/ 下会改动的文件、却没有声明对应的 lib/ 构建产物 ⇒ 提示（本仓库强制 lib/ 与 src/ 同步，成员 build 后必然产生 undeclared 路径）

输入面：task
contract.verify-command 2 个输入 按 kind 适用

契约里声明的 verify 命令必须可判（既能为做对的工作变绿、也能为做错的工作变红）：空命令、写死的真/假、以及拿 -x 去比"命令输出"（如 grep -qx N <(wc -l …)，前导空格让整行匹配永远不成立）都会在【建任务那一刻】被说清楚

输入面：task execVerifyCommand
contract.task-atomicity 1 个输入 按 kind 适用

★ 它判的是【契约声明面的形状】，不是「原子性」本身 —— 三条可机械读出的信号：verify 的条数与覆盖面、inScope 是否跨了概念上独立的目录组、objective 是否列了多个并列交付。★ 判定信号是【inScope 里有没有"没被更具体声明覆盖的目录前缀"】（归一化之后的集合覆盖，`src/` 与 `src` 是同一个键）—— 那是一个**语法层面**的结构读数：它**不读盘**，所以它判不了"这个目录是不是新建的"。★ 而"形状看起来不原子"只是"失败可能不可归因"的一个【征兆】，不是它的判据（t43 已用"只差一个尾斜杠的同一件工作"证伪过那个更强的声称）。判不了时报 unmeasured（绝不当成原子）。★ 本判据【不接生产】（t38：接线会让没有 verify 的任务全部建不出来）

输入面：task

交付 delivery · 2 条

delivery.coverage 1 个输入 按 kind 适用

用户目标的每个条目都必须有任务声称覆盖它；有目标无人认领 ⇒ 交付时拒绝（其余任务全绿会让"没人做的目标"看起来像都完成了）

输入面：team
delivery.convergence 1 个输入 按 kind 适用

交付时每个成员都必须处在收敛态；working / unknown / 空白回复都不是收敛 ⇒ 拒绝（idle ≠ converged，空回复不是收敛）

输入面：team

运行中 runtime · 2 条

runtime.liveness 2 个输入 按 kind 适用

周期性探活：两次探活之间最后活动时刻没变 ⇒ 告警「卡死了」；还在活动 ⇒ 只报「还在跑，已 N 分钟」。永不因为等太久而说话（它是探活，不是硬超时），也不拒绝任务（契约 §5）

输入面：event waits
runtime.stall 2 个输入 按 kind 适用

★ 它判的是【这个任务是不是停下来了】—— 依据是任务记录上**已经被数出来**的事实：同一个 (task, gate) 被拒的次数 ≥ N，或任务在 in_progress 上超过了 N 轮。★ 它**不读成员的自报**（一个卡住的成员恰恰最不可能如实说"我卡住了"）。★ 它【记录，不拒绝】：runtime 位置的裁决不得阻止流程。★ 而"说不出"（任务面整个没接上）是**第三态**，绝不当成"没人停住"。

输入面：event team

④ ★ prompt 里的机制：哪一条只是"一句话"

用户的判断是对的：这个插件的 captain protocol 是 10 条纯 prompt 规则， 它们注入系统提示词，而有一部分没有任何机械判据在背后。 下面把每一条规则与判据层做对照 —— ★ 而"没匹配上"不等于"没有机械判据"：有的规则天生无法机械判（那是三态里的 prose-only，不是"漏了"）。
匹配用的是关键词启发式，所以每一条都印出它是靠哪个词匹配上的，供复核。

⑥ 怎么重跑这张页

★ 它读的是 lib/（编译产物），因为那才是进程实际加载的东西。 改了 src/ 之后要先 build。 

cd ~/Desktop/agent-teams-dev
pnpm build                        # 先让 lib/ 与 src/ 同步
node scripts/mechanisms-html.mjs  # 重新生成 docs/mechanisms.html

生成的判据数、工具数、规则数全部来自运行时求值 —— 某个机制没在装配清单里，它就会出现在第 ③ 节，而不是被悄悄算进"已有机制"。
