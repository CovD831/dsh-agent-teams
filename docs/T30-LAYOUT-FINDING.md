# t30 的前置发现：成员行之间的空白（MEASURED 2026-10-11）

## 由来

用户看到侧边栏的团队面板"无法正常显示，好像有一定的放大和截断"，并且**点击看不到
成员内部情况**。用户还反馈**打不开浏览器控制台**，所以队长改为**自己探查**。

**这份文档的存在理由**：t30 在失败后**契约不可再编辑**，而下面的读数是在它失败
**之后**才测出来的。如果只写在对话里，下一个人接 t30 时会**重新猜一遍** —— 而
这一轮反复证明"重新猜"比"留下读数"贵得多。

## ① 已经排除的（都不是原因）

| 假设 | 实测结论 |
|---|---|
| CSS 没加载 | ❌ 列宽与声明**逐一吻合**（见下） |
| 头像是"巨大"的 | ❌ 我忘了除以 Retina 2×，实测 43.5 CSS px vs 声明 42px ✅ |
| 展开层在占位 | ❌ 折叠时**根本不渲染**（结构探针数出 0 个） |
| CSS 产物没生成 | ❌ `lib/client.js` 里 4 个 `data-plugin-css` 注入点与完整 CSS 文本都在 |
| 构建陈旧 | ❌ stamp 与 HEAD 一致，且 bundle 里有 R2 的 4 列规则 |

## ② 行本身是**对的**（像素测量，截图是 2× Retina）

以行左边缘为 0，实测（已折半为 CSS px）：

| 实测 x | 宽 | 对应 | 声明 | |
|---|---|---|---|---|
| 33.0–34.5 | 1.5 | 左侧竖线 | 1px | ✅ |
| **60.5–105.5** | **45.0** | 头像 | 列 1 = 46px | ✅ |
| **111.5–127** | **15.5** | 状态点 | 列 2 = 16px | ✅ |
| 135.5–145 | 9.5 | 箭头 | — | ✅ |
| 173–201.5 | 28.5 | 文字 | 列 3 | ✅ |

**行高 43.5 CSS px** vs `min-height: 48px` ✅

⇒ 所以 `grid-template-columns: 46px 16px minmax(0,1fr) 96px` **确实生效**。

## ③ 错的是**行与行之间**

```
行 1 顶部:  y = 621 (物理)
行 2 顶部:  y = 1261
⇒ 行距 640 物理 px = 320 CSS px

而样式声明只有:
  .memberBlock   padding: 3px 0 7px     = 10px
  .delegationTree gap:    2px           =  2px
                            合计        = 12px

⇒ 实测是声明值的 26 倍
```

而那 320px 空白里**只有两个孤立的小点**（x=107 与 x=272），**没有任何文字**。

## ④ DOM 结构是最小的（受控复现）

队长挂起**真的 `TeamSection`**（复用 `workspace-activity.test.mjs` 的最小 DOM 与
宿主 stub），打印出结构：

```
.delegationTree[data-member-rows=2]
  .memberSlot
    .memberBlock
      <span .memberBranch>        ← 绝对定位，不占布局
      <button .memberRow>         ← 恰好 4 个网格子元素，与 4 列吻合
        <span .memberAvatar>  <span .memberDot>
        <span .memberInfo>    <span .memberStatusTail>
```

**折叠时 `memberSubagents` 容器数量 = 0。**

⇒ 所以**行内没有多余元素占位** —— 空白**不在行内**。

## ⑤ ★ 缺的那一个读数

最小 DOM **没有布局引擎**（`getBoundingClientRect` 恒返回 0），
而截图只能给"渲染后的像素"。

**⇒ 两者之间缺的正是"计算后的样式"（computed style）。**

⇒ 而用户打不开 DevTools，所以队长**停在这里**，没有继续猜 ——
这一轮的教训之一就是"没量就下结论"会错（见 §① 的 Retina）。

**⇒ 接 t30 的人要做的就是补上这个读数，在一个真实浏览器里。**

## ⑥ 顺手测到的一条死规则

```css
.memberSlot[data-has-model='true'] { overflow: hidden; text-overflow: ellipsis; white-space: nowrap; }
```

**`data-has-model` 在全部 `.tsx` 里从未被设置过**（grep 实测）。
⇒ 它是一条**读起来像在管事、实际不生效**的规则。**删掉它**，或让它真的被设置。

## ⑦ 给 t30 的验收（它失败后契约已冻结，见本文档开头）

1. 拆分的**集合比对**（既有要求）
2. **行距必须等于声明值**：相邻行**顶部**相距 12px + 行自身 48px
   —— 而**必须由真实浏览器测量确认**，不是读样式表
3. 测量**走侧边栏路径**（`WorkspaceActivity → TeamSection`），
   因为**那是用户看到缺陷的那条路**，而**它此前从没有样式测试**
4. 删掉 §⑥ 那条死规则
5. 每条新臂都要有**反向的一半**

# ⑧ ★ t36 补上的那一个读数：**计算后的样式**（MEASURED 2026-10-12）

§⑤ 停在这里是对的：最小 DOM 没有布局引擎，所以那份文档明确把"真实浏览器里的
computed style"列为**下一个接的人必须补的读数**。这一节就是它。

## 怎么量的（可复现）

用**机器上已有的** headless Chrome 154（DevTools Protocol，Node 自带 `fetch` + `WebSocket`，
**没有新增任何依赖**），把**真实编译产物里的样式表**（`lib/client.js` 的 `css$3`，
55 841 字符，类名是 `_8qZE2a_*` 哈希）与**§④ 打印出来的那套真实结构**放进同一个页面，
然后 `getComputedStyle` + `getBoundingClientRect`。

页面按**侧边栏那条路**搭：`WorkspaceActivity .root`（`container: team-workspace / inline-size`）
→ `.content`（`padding: 12px 20px 28px`）→ `TeamSection`（`data-workspace-team`）。

## 读数：行距**不是** 320px —— 在任何一个宽度下都不是

相邻**行顶**之差（CSS px，`memberRow` 的 `getBoundingClientRect().top`）：

| 侧边栏宽度 | 列的宽度 | 行高 | **相邻行顶之差** |
|---|---|---|---|
| 1440 | 528.5 | 50 | **62.0** |
| 900 | 860 | 50 | **62.0** |
| 700 | 660 | 50 | **62.0** |
| 420 | 380 | 50 | **62.0** |
| 388 | 348 | 50 | **78.2** |

而**展开**（点开成员、`memberSubagents` 容器数 = 3）之后：

| 状态 | 行高 | 行块高 | **相邻行顶之差** |
|---|---|---|---|
| 折叠 | 50 | 75 | **77.0** |
| 展开 | 50 | 98 | **100.0** |

⇒ **62px 正是声明值**：`.memberRow` 自身 50px（`min-height: 48px`，内容撑到 50）
＋ `.memberBlock` 的 `padding: 3px 0 7px`（10px）
＋ `.delegationTree` 的 `gap: 2px`（2px）
**= 62px**。实测与声明**逐项吻合**，不是 26 倍。

⇒ 而 388px 那一列变 78.2px，是因为 `@container _8qZE2a_agent-team (width<=360px)` 之外的
窄态让 `memberStatusLine` 换行 —— 方向相反（更宽不是更窄），且仍与 320 相去甚远。

## 那 320 从哪来？—— 算术上它不可能是"相邻两行"

§③ 说 621 与 1261 是**物理** px，于是 640 物理 → 320 CSS。而 §② 的逐项测量**也**做过
同样的折半（头像 45 CSS vs 声明 46 ✅），所以折半口径是**一致的**。

那么 320 ÷ 实测 62 = **5.16 倍**，320 ÷ 展开时的 100 = **3.2 倍**。
**这两个都不是任何合理的缩放系数**：

```
x1 x 62 =  62      x3 x 62 = 186      x5 x 62 = 310
x2 x 62 = 124      x4 x 62 = 248
```

⇒ **640 物理 px 不可能是同一张卡里相邻的两个成员行**。最可能的是那两个 y 坐标
**不是相邻行**：例如跨了两张团队卡（侧边栏会为每个 team 渲染一个 `TeamSection`）、
或者取自一个行与一个相距很远的元素。**这一条我没有直接证据**，如实留在这里，
不当作结论 —— §① 的 Retina 教训正是"没量就下结论会错"。

## ⑨ 顺带确认的：`data-workspace-team` 的双列网格**确实存在**

宽 ≥1000px 时，编译后的样式表里有：

```css
@container (width>=1000px){
  .team[data-workspace-team]{
    grid-template-columns:minmax(260px,.85fr) minmax(0,1.35fr);
    display:grid; column-gap:32px; align-items:start;
  }
}
```

实测在 1440 宽时确实生效（`getComputedStyle(team).display === 'grid'`，
`gridTemplateColumns === "528.531px 839.469px"`），900 及以下回落为 `flex`。

⇒ **这条规则是真的、也确实在管事** —— 而它并**没有**造成行距异常（1440 与 900 的
行距都是 62.0）。所以"两个屏共用一个网格"这件事在**行距**上是无辜的；
它仍然是"两块内容挤在一个容器里"的结构问题，拆分依然是对的，
但**不要**把行距缺陷归到它头上。

## ⑨b ★ 那 320 的**成因**（队长追认，2026-10-12）—— 这一节把问题关掉

上一节说"我没有直接证据、不当作结论"。队长随后把成因**自己**补上了，现记录如下：

> 那 320 来自一张**截图**，不是来自布局引擎。本文档 §④ 已经写明最小 DOM 没有布局
> 引擎（`getBoundingClientRect` 全 0），所以 §③ 的 y 坐标只能来自**渲染后的像素图**。
> §③ 从那张图上取了两个 y 值（621 与 1261 物理 px，相差 640）**并断言它们是相邻的两个
> 成员行** —— 而这个配对**从未被验证过**。

⇒ 所以：**行距从来没有错过**。声明 12px、渲染 62px（含 50px 行高），在每一个宽度上都是。
320 是一次**量测错误**，与 §① 已经犯过一次的 Retina 错误**同一族**（把图上的像素
当成了布局事实，而跳过了"去真实浏览器拿计算样式"这一步）。

★ 这一节的意义不是"谁错了"，而是：**一个未经验证的配对（"这两个 y 是相邻两行"）
被写成了结论，然后被当成缺陷去找了整整一轮。** 而它被推翻，靠的是补上那个
§⑤ 早就点名缺掉的读数 —— computed style。

## ⑩ 死规则

§⑥ 说的那条：

```css
.memberSlot[data-has-model='true'] { overflow: hidden; text-overflow: ellipsis; white-space: nowrap; }
```

`grep -rn "data-has-model" src/client/*.tsx` ⇒ **0 处**。t36 删掉它（见 §⑦ 第 4 条）。

## ⑪ 一条会伪装成"布局塌了"的量测陷阱（t36 实测，写下来给下一个人）

我裁剪掉死 CSS 之后重新量，读数变成 **行高 21px、行距 21px、而且五个宽度全都一样** ——
看起来像"我把样式裁坏了"。**它不是。**

根因：我的量测脚本里**硬编码**了 CSS-Modules 的哈希前缀 `_8qZE2a_`，而
lightningcss 是**按文件的绝对路径**算哈希的 ⇒ 换个 worktree 重建，前缀就变成
`EpOeea`。于是那个页面里的 `class` **一个都匹配不上**，量到的 21px 是**没有样式**的高度。

⇒ 修法：**前缀必须从样式表里现推**（`/\.([A-Za-z0-9_-]+)_memberRow\b/`），
不许写死。写死的结果不是"报错"，而是**一个看起来很合理的错数字** ——
而它比报错危险得多，因为它会让人去修一个根本没坏的东西。

修好之后读数**逐项复现**：1440/900/700/420 都是 62.0，388 是 78.2。

★ 这一条的教训与 §① 的 Retina、§③ 的 320 是**同一族**：量测工具本身出错时，
  它给出的不是一个"错误"，而是一个**像样的数字**。
