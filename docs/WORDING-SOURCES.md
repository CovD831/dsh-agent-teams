# j-0007：措辞里的兜底值 —— 谁给那个数字赋的值

**判据**：`scripts/gate-wording-sources.test.mjs`（8 条臂）
**结论**：这条判据把「一句描述机制行为的话，可以从未被兑现过 —— 而它读起来与兑现了的话完全一样」
变成了一个**可机械判定**的问题。

---

## §1 它防的是什么（两个真实实例，各出现过一次）

### ① t56 —— 一个恒取兜底值的数字

`changed-paths.ts` 的拒绝消息里曾写着：

```
…not in any of the ${ctx?.observedWorkspaces ?? 1} workspace(s) that were checked
  (the main workspace and every member worktree under it)
```

而 `observedWorkspaces` **从来没有被任何地方赋过值** ⇒ 恒 `undefined` ⇒ `?? 1` **恒取 1**。

★ 于是那句"扫了 N 处"里的 N 是一个**硬编码的兜底值**，而那句括号
（"主工作区**及其下每一个**成员 worktree"）是**一句从未兑现的承诺**：
代码里当时没有那件事。

### ② t73 —— 数据与它自己的理由互相否

`kind-requirements.json` 的 `verification` 一节里，
`requiredGates` 说要 `r5`，而同一行的 `because` 说不要。

★ 那一次**不是**"两个值冲突"，是**数据与它自己的理由互相否** ——
两者都在场、单独看都合理，**并排读**才发现它们说的是两件事。

## §2 ★★ 判据的形状（它为什么窄、为什么可机械判定）

问：**那句话里的每个值，能不能指出它【由谁赋值】？**

```
有赋值点                       ⇒ 合格
没有、而兜底值是字面量          ⇒ blocked   ← 那就是缺陷
无法判断（动态赋值 / 仓外来源）  ⇒ 第三态，如实报
```

★ "谁给它赋的值"是**可查的**（grep 那条属性路径的产出面）——
这就是它比"措辞好不好"窄得多、也硬得多的原因。

## §3 ★★★ 附条件（写进判据本身，不靠使用的人记得）

用户 2026-10-08 的标准：**「特定条件下起效的也能加，只是需要把那些特定条件顺便加上去。」**

⇒ 本判据**只在**下列条件同时成立时适用，三条都写在代码里、且臂 6 逐条核对：

| 条件 | 内容 | 为什么 |
|---|---|---|
| (a) | 那个 `${…?? literal}` 出现在**面向人的措辞**里（拒绝消息 / 日志 / 状态行） | 本判据的观察对象是**措辞**，不是所有 `??` |
| (b) | 被兜底的是一条**属性路径**（`a?.b ?? x`），不是裸局部变量 | 裸变量查不了赋值点 |
| (c) | 那条路径的**根**在本仓里可解析 | 仓外来源（宿主注入）判不了 —— 判红就是**误伤** |

★ (c) 是必须的：本仓看不到宿主往 `ctx` 里塞了什么。⇒ 判据对这种情形说 `unreadable`。

## §5 ★ 三态必须互不同形（否则会误伤）

```
assigned    —— 找到产出面（对象字面量赋值，或"某函数返回了它"的类型产出面）
unassigned  —— 找不到，且那条路径的根是本仓可达的 ⇒ 那就是缺陷
unreadable  —— 判不了（裸局部变量 / 只有动态下标的写入 / 仓外来源）
```

★ 第三态**不是礼貌，是精度**：一个只判"有没有赋值点"的实现会把
`task?.kind ?? 'unspecified'` 也判红，而那一格**合理**（`kind` 是可选字段）。
⇒ 缺陷的形状**不是**"用了 `??` 字面量"，而是：

> 那句话声称了一件**关于机制做过什么**的事，而那个值**没有任何来源**。

## §6 ★★ 三次实测纠错（本判据自己踩过的假阴性 / 误伤）

这份判据的第一版**误报 10 条、假阴性 1 条**。三次都记在这里，因为它们是同一类错误的三个面：

| 版本 | 错法 | 形态 |
|---|---|---|
| ① | `baseline.stdout ?? ''` 被判**无来源**（误伤 10 条） | `.stdout` 来自一次真的子进程调用，只是它的产出面写在**返回值类型注解**里 ⇒ 一个只认"对象字面量 `leaf:`"的检索看不见它 |
| ② | 删掉赋值点后，存量仍报"合格"（假阴性） | 把**类型声明** `x?: number` 当成了产出面 —— **声明不是产出**，它不产生任何值。把声明当来源 = 判据永远绿 |
| ③ | 编造一个不存在的路径，竟报 `unreadable`（假阴性） | 只要行内出现 `root[` 就记成"可能有动态写入" ⇒ **每一个** `ctx.x` 都因此落 unreadable。那些正是**注入还原循环**（`ctx[key] = value`）——它是**还原**，不是那个值被**产生**的地方 |

★ 三次的共同形态：**一个"看起来像来源"的东西不是来源** ——
类型注解、类型声明、泛型还原循环。而它们的危险一致：**都让判据看起来更保守**。

## §8 已知边界（写出来，不假装覆盖）

- 行尾注释（`foo() // ${x ?? 1}`）**不**被剥 —— 那种写法不存在于本仓，
  而剥它需要一个会被字符串字面量骗到的解析器。⇒ 宁可少剥不可乱剥。
- "产出面"只认出三类形状：对象字面量赋值、返回值类型里的字段、具名下标写入。
  ⇒ 一个用更绕的方式产出值的实现会被判 `unreadable`（**不是** blocked）——
  那是**精度**的选择，不是漏报。
- 本判据只管**措辞**。`const x = a ?? 1` 这种**非措辞**的兜底不在范围内，
  它有自己的读者（类型系统）。
