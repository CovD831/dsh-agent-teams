# 提案：一条「交付回流」判据（堵住沉默的失败）

> **状态**：提案，**未实现**。由 2026-10-15 本队实测的一次真实事故触发。
> **读者**：下一个会话 / 决定要不要接这条判据的人。

---

## 1. 事故（MEASURED，不是设想）

**t18 报告**：「F1 已修，两条文档已提交（commit `e7c617b`），worktree 干净。」

**实测**：

```sh
$ git branch -a --contains e7c617b
（空 —— 不在任何分支上）

$ git worktree list | while read p _; do
    git -C "$p" merge-base --is-ancestor e7c617b HEAD 2>/dev/null && echo "$p"; done
.../.agent-teams/worktrees/task-agent-teams-refactor-t18
```

⇒ 提交**只在该任务自己的 worktree 里**，**没有回流到队长工作区**。

| 文件 | worktree 提交 | 队长工作区（当时） |
|---|---|---|
| `docs/GATE-EFFICACY.md` | 546 行 | **461 行（含 blocker 的旧版）** |
| `docs/GATE-EFFICACY-CONTEXT.md` | 243 行 | 292 行（内容不同，md5 不同） |

## 2. 危害：它会让复核**得出与事实相反的结论**

复核员读的是**队长工作区**，实现者写的是**自己的 worktree**。两者之间的桥**没有人负责**。

- 本队实测：复核员（t19）**独立发现**了这件事，并明确写下
  「**不归并的话，「已修复」在主场不成立**」。
- 而它**只能靠读行数与 commit 祖先关系手工发现** —— 这是一条**没有判据**的失败。

★★ 若队长没有在复核前手工取回，复核员会看到**已被判定为错的那一版**，
   从而判「blocker 未修复」—— **而那与事实相反**。

## 3. 它是什么样的失败

★ 这正是本仓记账最久的那条形态的又一实例：

> **一个关于代码的结论，由一次基础设施工况伪装出来。**

只不过这次的伪装是「**交付物在两个地方，而只有一处被读**」：

- 成员**没有撒谎** —— 它确实写了文件、确实提交了、`git status` 确实干净；
- 复核员**没有粗心** —— 它读的就是约定的那棵工作树；
- ⇒ **两边都对，而结果是错的。**

★ 而本仓已有判据 `dispatch.worktree` 管「**隔离目录建得出吗**」，
  **却没有判据管「东西交回来没有」** —— 缺的正是这根线。

## 4. 判据提案（可机械判定、可证伪）

### 4.1 形状

```
id      = 'completion.deliverable-return'
point   = 'completion'
闸门    = 任务带 changedPaths 且该任务有 worktree（ctx.worktree?.dir 在场）

判据（三态）：
  1. 取该任务提交里的每个 changedPath 的内容哈希
  2. 取队长工作区对应路径的内容哈希
  3. 逐条比对
     · 全部相等        ⇒ ok
     · 有不等          ⇒ blocked，并逐条列出「哪几个文件、两边的哈希」
     · 读不出（文件不在任一侧 / 不是 git 仓） ⇒ unmeasured（★ 不许并进 ok）
```

### 4.2 ★ 为什么它必须区分三态

★ 本仓最贵的一条纪律：**「可判定的事实」不得写成「没能测量」**，
而 **`skipped` 与 `ok` 必须不同形**。

⇒ 「文件不在任一侧」与「文件在两侧但不相等」**处置相反**：
   前者可能是**新增文件尚未落盘**（正常的中间态），后者是**交付物没回流**（真失败）。
   两者**不许读成同一件事** —— 否则这条判据会像 `catch{}` 一样，
   把「读不到」与「不一致」混成一个读数。

### 4.3 反向半边（可证伪性：必须有）

★ 本仓的判据纪律：**每条判据都要有一条「把它弄坏就必须红」的臂**。

```
构造：把队长工作区某文件改一个字节（不回填提交）
预期：本判据立刻红，且指出是哪一条路径、两个哈希各是什么
```

没有这条臂，判据无法与「恒绿」区分。

## 5. 为什么它值得接（而不是"多加一条判据"）

1. **它堵的是沉默的失败**：目前只有"人碰巧发现"这一条路。本次是**队长先发现、复核员再独立发现**才没出事 —— 两次都靠运气。
2. **它的输入已经全在契约上**：`changedPaths` 是 `implementation`/`repair` 的**必填格**，
   worktree 目录由 `dispatch.worktree` 给出 ⇒ **不需要新增任何输入面**。
3. **它把「谁负责那座桥」变成可判定的**：现在这座桥**没有人负责**，
   而"没人负责"在记账上与"负责了但没做"同形。
4. ★ 它也是**判据形态**的一个正例：闸门在**模块边界**（"交付完成"这个边界）上，
   校验的是**输入输出**（提交里的内容 vs 队长工作区的内容）—— 正是本仓既有的形状。

## 6. 边界（本提案不做的事）

- **不**自动归并（不 `git merge`、不 `git checkout`）—— 判据只**报告**，
  归并动作是人的决定（本仓纪律：判据不替人做决定）。
- **不**处理「两条工作树都改了同一文件」的冲突 —— 那是另一类问题。
- **不**改变 `dispatch.worktree` 的现有语义。
