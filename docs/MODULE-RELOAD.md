# 进程内换模块：一次探针，与一条负结果

> **判定：不可行（`infeasible`）。**
> 不是"技术上做不到换代码"—— **那部分真的做到了**。
> 是它的代价落在一个**无法支付**的地方：本队承重的那一格状态**没有入口**，
> 而混代（新代码 + 旧状态）**静默**。

复现：`node scripts/probe-module-reload.mjs`（人读）· `node scripts/probe-module-reload.mjs --json`（机器读）
夹具：`node --test scripts/probe-module-reload.test.mjs`（14 臂）

---

## 一、问题是什么

`pnpm build` 之后，**已经运行着的插件进程**里还是旧代码 ——
因为 ESM 的 `import` 在**模块求值时**建立绑定，之后永远指向同一个函数对象。

于是「自动重载」要回答的是：**能不能在这个进程里换掉模块，而不是重启它？**

captain 实测了一个关键事实（本探针复核，**成立**）：

```js
await import(path + '?v=2')   // ⇒ 真的重读磁盘，拿到新代码
await import(path)            // ⇒ 复用缓存，仍是旧代码
```

⇒ 所以「进程内换模块」**在技术上确实可行**。**而结论是不可行** —— 下面是为什么。

---

## 二、★★ 换掉的是「模块」，不是「模块图」

这是本探针最根本的一问，而它的答案与直觉相反。

```
entry.mjs  ──import──>  tool.mjs  ──import──>  shared.mjs (持有 state)
```

对 `entry.mjs` 加指纹重新 import 之后：

| 模块 | 被重新求值了吗 | 为什么 |
|---|---|---|
| `entry.mjs` | **是** | 它的 specifier 带了新 query |
| `tool.mjs` | **否** | 它内部的 specifier `'./tool.mjs'` **没有 query** ⇒ 命中同一个缓存 |
| `shared.mjs` | **否** | 同上 |

⇒ **指纹只作用在它被应用的那一个模块上。** 换掉的是「模块」，**不是**「模块图」。

**而后者才是真正需要的** —— 本队的 `tools.ts` 现在是 16 个模块 + 88 个实体。

### ★ 而这一条同时纠正了一个说法

> 「带 query 重新 import 会让状态分裂从 N 份变成**每一代构建一份**。」

**实测：分裂没有发生。** 因为依赖没有跟着被指纹化 ⇒ state 是**同一份**。

⇒ 而结论不是"所以没问题"。是**问题换了一个更坏的样子**：见下一节。

---

## 三、★★ 混代：新代码 + 旧状态，而它静默

既然 state 是同一份，那么重载后的世界是：

```
   新代码   +   旧状态
```

**而这两者本来是一起演进的。** 一次平常的重命名就能让它裂开：

```js
// 第 1 代：写 state.waitRecords
// 第 2 代：读 state.waitWindows      ← 一次平常的重命名
// 而 state 还是第 1 代那份
```

实测结果：

| 读数 | 值 |
|---|---|
| 新代码读新字段 | `undefined` |
| 旧字段是否还在 | **在**（所以"看起来"没坏） |
| **有没有抛错** | **没有** |

⇒ **混代是静默的。**

★ 这正是 absorb-dev 在 t39 写下的那句：

> 「状态分裂成 N 份，而分裂**不会当场报错** ——
>  它表现为『status 看不到 update_task 写的 wait 记录』，
>  而那个症状与『这个成员确实没在动』**同形**。」

---

## 四、★★ 承重的那一格状态，没有入口

这是判「不可行」的**决定性**一条。

`src/tools/shared/entities.ts` 里：

```ts
let requestedRestart: { at: number; waitingOn: string[] } | undefined   // ← 没有 export
```

⇒ 它**不可读、不可写、不可迁移**。一个指纹化的新实例看不见它。

**而它正是「排队重载」这条机制的状态**（本队最近两次提交的主题）。

实测：

```
旧实例：pendingRestartRequest() ⇒ { at: 12345, waitingOn: ['t1','t2'] }
新实例：pendingRestartRequest() ⇒ undefined
```

⇒ ★★ **一次重载会把它自己的触发申请丢掉。**

### ★ 而这不是"一刀切"

有导出的容器（`waitRecords` / `runtimeGateLog` / `waitWindows` …）**可以**逐条拷贝
（臂 8 专门钉住这一条，防止"模块状态一律不能迁移"这种过头的结论）。

⇒ 判不可行的理由**不是**"状态都不能迁移"，是**承重的那一格没有入口** ——
`requestedRestart` 不是"迁移很麻烦"，是**没有迁移的入口**。两者不同形。

---

## 五、旧实例能否被丢弃

| 问题 | 读数 |
|---|---|
| 新实例会继承旧实例的订阅吗 | **不会**（`Set` 是空的） |
| 旧实例的订阅还在工作吗 | **在** |
| "把订阅搬过去"可行吗 | **按引用可以**，**按语义不行** |

★ 最后一行是关键：订阅者通常是一个**闭包**，它捕获了别处的东西。
搬过去的是一份引用，而那个闭包**仍然闭在旧模块的作用域上** ⇒ 搬过去的是"半旧"的东西。

★ 而这两个读数必须**分开**：合成一个"能不能搬"会掩盖真正的困难。

## 六、三态

| 取值 | 含义 | 何时发生 |
|---|---|---|
| `feasible` | 可行 | 三条机制级障碍都不成立 |
| `infeasible` | **不可行** | 至少一条成立 ← **本次** |
| `undecidable` | **判不了** | 真实插件模块不可用（没 build / 没有 `lib/`） |

★★ `undecidable` **绝不写成** `feasible`。臂 11 把这一条钉成可执行断言，
而它同时断言 `feasible` 是一个**真会发生的**取值 ——
否则 `verdictOf` 会退化成一个恒为"不可行"的函数，而那种臂是恒真的。

## 七、判定与它的三条理由

```
★★ 判定：infeasible

· 一个【私有】模块级 let（["requestedRestart"]）持有排队重载的状态，
  而它没有 export ⇒ 指纹化的实例读不到它、迁不了它、也不会被告知它。
· 一次"换代码而留状态"的重载，会让新代码对着旧状态跑，而它是【静默】的
  （读出来是 undefined，而没有任何一处抛错）。
· 指纹只重载它被应用的那一个模块 ⇒ 单独指纹化 entry 会得到
  "新 entry + 复用的依赖"，它没有换掉模块图。
```

★ 每条理由都**指名一个读数**，而每个读数都能在这一页复现 —— 不是一句"代价太高"。

---

## 八、★ 已知边界（即使可行，也要付什么）

这一节是**为了下一个人**：如果将来某条路绕开了上面的障碍，代价仍然在这里。

1. **状态迁移是 O(实体数) 的手工工作。** 每一格可迁移的导出容器都要显式搬；
   而**漏掉一格不会报错** —— 它与"本来就没有"同形。
2. **私有状态是硬边界。** 任何 `let` 没有 export 都不可迁移。
   ⇒ 若要走这条路，必须**先**把承重状态改成"有显式出入口"的形状，
   而那是一次源码重构（`src/` 的写域），不是重载机制能顺手解决的。
3. **模块图不会跟着换。** 要换整张图，需要**递归地**给每一个 specifier 加指纹 ——
   而 ESM **不允许**在运行时重写别人的 specifier。
   ⇒ 可行的替代是：让**宿主**用一个带指纹的**入口**重新加载整棵子树
   （即"重启"），而不是在进程内换。
4. **值不值得，要用户裁定。** 本探针只回答"可不可行"与"代价是什么"，
   不回答"值不值"。★ 而它给出的是一个**有据的负结果**：
   「自动重载」应当降级为**告知**（"这个进程旧了，请重启"），
   而不是在进程内偷偷换 —— 而那个告知**已经有了**
   （`moduleFreshness()`，t42 给它补上了提交维）。

---

## 九、★ 一条与本队其余台账同源的归纳

本探针复核 captain 的实验时发现一处**报告与实测不符**：

> captain：「普通 import 两次 ⇒ `a === b` 为 `false`（那说明每次都新建）」
> 实测：**`true`** —— 同一 specifier 的两次 `import` 是**同一个模块对象**。

★ 而这一条不是细节：**整条"缓存复用"的前提就建立在它上面**。
若"每次都新建"成立，那么"带指纹能拿到新实例"就毫无信息量。

⇒ 它与本队今天归纳的那条同源：

> **一个写在某个时刻的事实，在没有被复核的情况下继续被当成本刻的事实。**

而这一次它出现在**实验报告的读数**里 —— 而那个读数**本可以当场再跑一次**。
