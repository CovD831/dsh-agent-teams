## 2. ★★ 形状：**不许读源码文本**（本判据的全部要点）

`grep "gateEvaluationRecordOf" src/state/tasks.ts` **不是判据**，两条理由：

| # | 它怎么骗过人 | 本仓的先例 |
|---|---|---|
| **①** | **改名/挪文件就失效** ⇒ 能力**还在**而判据**假红** | ★ t67/t70 那两次"按文件路径读源码"的夹具（`docs/E-LINE-L0.md` §4） |
| **②** | 测的是**文本**不是**能力** ⇒ 注释掉的、死代码里的符号名同样命中 ⇒ **假绿** | 同上 |

⇒ 本文件照 **`scripts/gate-position-wiring.test.mjs`** 的形状。它的注释逐字：
> 「所以本文件的每一条断言都必须是【**实测**】的：往注册表上真的挂一条判据，
>   真的走一次工具路径，然后检查判据【自己被调用了】。」

★ **具体到本文件**：每一条能力的 `check` 都是一个**可执行的函数**，
它**真的 `import`** 那个模块、**真的走一次工具路径**，然后读**盘上的事实**。

## 3. ★ 清单：一条能力一格（**怎么加一条**）

```js
{ id, capability, symbols, check }
```

| 字段 | 作用 |
|---|---|
| `id` | 短名（`S1` / `T5` / `T8`），**不许重复** |
| `capability` | 它是什么能力（读的人要知道"没了"意味着丢什么） |
| `symbols` | 该能力依赖哪些导出（人读面，也是"谁没了"的读数） |
| ★ `check` | **一个函数**：真的去执行那件事，并 `return` 读数 |

**加一条的动作 = 加一个对象。** ★ **刻意不写成一个巨大正则** —— 那样加一条要改正则，
而**正则会腐烂**；而且改正则时你不知道改的是哪条能力。

★ 而"`check` 必须是函数"这件事**由臂 4 当场挡下**：
```js
assert.equal(typeof entry.check, 'function',
  `★★ \`${entry.id}\` 的 check 必须是**可执行的函数**，不许是正则或源码文本`)
```
⇒ 于是"有人图省事写成 `grep`"这条路**在判据层就被堵住**，而不是靠纪律。

### 3.1 现有三条

| id | 能力 | 关键符号 | 检查方式 |
|---|---|---|---|
| **S1** | 判据结果落盘到 task（B 线唯一的服务端前置） | `gateEvaluationRecordOf` + `task.gateEvaluation` | ① `import` 产物并断言该导出可调用（**整个符号被删 ⇒ 红**）；② 喂一份**真实的** `GateEvaluation` ⇒ 断言 `ran[]` 保序且全在、`registered`/`evaluated` 在 |
| **T5** | 闸门判定：inScope 里"结构上不可能产出"的路径 | `emittedProductGaps` | 真跑：只声明 `src/state/tasks.ts` ⇒ **必须报出缺口**；★ 对照：把产物**声明齐** ⇒ 缺口**消失** |

## A1. 洞是**真实存在**的（实测）

`test:gates` 用 **glob** 选夹具：`scripts/gate-*.test.mjs`。
★ 而 glob 的性质是「列出**此刻磁盘上**匹配的东西」：

```sh
$ ls scripts/gate-*.test.mjs | wc -l
89
$ rm scripts/gate-stale-module.test.mjs
$ ls scripts/gate-*.test.mjs | wc -l
88          # ★ 数字变了，而 test:gates 的命令串【一个字都没变】⇒ 没有任何东西会报
```

⇒ ★ 这正是那次事故的形状：**能力与它的判据被同一次提交一起抹掉**，而 `tsc` 绿、门禁绿。

## A2. ★★★ 基准放在哪（本任务的核心难点）

**先说为什么不能写成仓里的一个清单文件**：那样"删夹具 + 改清单"**是同一件事**
（一次提交、一个 `git add -A` 就够）—— 而那正是本次事故的**手法**。
⇒ **那种版本比没有更坏**（虚假的信心）。

**本判据用的基准**：**git 的"曾经新增过"记录**

```sh
$ git log --diff-filter=A --format=%H --name-only -- 'scripts/gate-*.test.mjs'   ⇒ 89 个名字
$ git log --diff-filter=D --format=%H --name-only -- 'scripts/gate-*.test.mjs'   ⇒ 0 个
```

★ `--diff-filter=A` 挑的是「**Added**」那种改动 ⇒ 它数的是**历史上被创建过的文件名**。
★★ **它防得住的原因**：提交是**追加**的 ⇒ **后来删掉某个夹具，不会把"它曾被新增过"抹掉**
⇒ 于是"曾有过 89 个"与"现在挂着 88 个"**出现差集** ⇒ **那差集就是信号**。

## A3. ★★ 「连判据带基准一起删，要做几件事？」（必答）

| 想抹掉的 | 要做什么 | 够吗 |
|---|---|---|
| 一个夹具 | 删文件（**历史仍记着它被新增过**） | ❌ **不够** |
| 夹具 + 本元判据文件 | 删两者（**历史仍记着**） | ❌ **不够** |
| 夹具 + 元判据 + **改写历史**（`rebase` / `filter-branch` / 改那条 add） | 改写历史 | ✅ **能** |

⇒ ★★ **如实报出边界**：本判据防的是「**一次普通提交**（含 `git add -A`）抹掉能力与它的判据」，
**不防"改写历史"**。
★ 而"改写历史"是**另一个量级**的动作：它会改掉**所有**提交哈希、需要 `push --force`、
在共享仓库里**看得见**。
⇒ 所以答案是「**不再是一件事**」：从"顺手一次 `git add -A`"变成"**一次会被察觉的历史改写**"。
★ 这就是本判据能提供的**全部**保证 —— **不多也不少**。

## A4. ★★★ 一处**如实留痕**：我第一版的算术是**错的**，而且错成"看起来能防、实际防不住"

我第一版写的是**比大小**：`onDisk.size >= everAdded.size`。
**它在我的树上就红了**，而查下去发现**不是测试写错，是算术不成立**：

```
磁盘上      : 90    ← ★ 含【本判据自己】，尚未提交
历史基准    : 89
删掉一个已注册夹具 ⇒ 90-1 = 89，而 89 >= 89 仍成立 ⇒ ★ 看不见这次删除
```

★ **根因**：`onDisk` 会被**未提交的新文件垫高基数**，而"工作了半天的树"里
≥1 个未提交夹具是**常态**（谁加新夹具时都是这个状态）。
★★ ⇒ 那个版本**看起来在防，实际防不住** —— 正是本任务警告的"比没有更坏"。

**改法**：判**差集**（历史里有、磁盘上没有的那些**名字**），**不是**比两个计数。
★ 差集**不受未提交新文件影响**（它们不在历史基准里 ⇒ 不会进差集）。
**实测**（同一棵树上）：
```
$ rm scripts/gate-stale-module.test.mjs
差集 ⇒ ["scripts/gate-stale-module.test.mjs"]   ← ★ 1 个，且**指名**
$ （恢复后）
差集 ⇒ []                                        ← ★ 对照：不删时为空
```

★ 并**加了臂 2 专门钉住这个错**：「未提交的新夹具不许把基数垫高」——
它要求"只在磁盘上、不在历史里"的那些**必须确实是未提交的新文件**
（若某个**已被跟踪**的文件也在那一侧，说明历史基准**漏读了它**，判据对它失效）。

## A5. 两条反向半边（都实测跑过）

**A · 真的删掉一个夹具文件**（★ 核心 —— glob 看不见的那一格）
```sh
$ rm scripts/gate-stale-module.test.mjs
$ node --test scripts/gate-registry-integrity.test.mjs
✖ ★★ 已注册夹具数不许减少：历史上新增过而现在不在的，必须为空
   ★ 报文里**指名**：scripts/gate-stale-module.test.mjs
```
★ **指名**是刻意的：只报"少了 1 个"会让读的人不知道**丢的是哪一条判据** ——
而那是他唯一能去修的东西。

**B · 把夹具从 runner 的清单里移走** —— 本仓的清单是 **glob（隐式）**，
所以"移走"等价于**把 glob 改窄**：
```sh
$ # 把 test:gates 里的 gate-*.test.mjs 改成 gate-a*.test.mjs
✖ ★ `test:gates` 必须仍然用 glob 选夹具（否则上面那两格的射程会静默变小）
```
★ 这一格防的是**反向的失效**：glob 换窄 ⇒ 大部分夹具**不再被跑到**，
而"数量没减少"**仍然成立** ⇒ **静默失效**。
