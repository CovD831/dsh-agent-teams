### N · 盘局 / 辅助支线（★ 新增一等线，用户"盘局优化"的落点）

**问题**（F6/F6b/F6c）：**8 个辅助支线机制全在 `scripts/`**，与 130 个测试夹具**平铺**在同一个目录里（169 个 `.mjs`），**没有分层**。而其中**只有 1 个（`friction-triage`）被生产引用**。

**这正是用户说的"做得比较散，没有制定一个计划"。**

| 步 | 动作 | 性质 |
|---|---|---|
| N1 | ★ **盘局地图**：把 39 个非测试脚本按**用途**分类，并标出每类的**归属**：运行时机制 / 开发工具 / 发布工具 / 一次性夹具 | 只读分析 |

| 选项 | 代价 |
|---|---|
| (甲) **维持现状**（动态 import） | 零成本，但支线永远在构建系统之外 |
| (乙) **把分诊逻辑移进 `src/`**，`scripts/` 只留 CLI 壳 | 一次性改动，之后支线与主线同屋；但会改构建结构 |

★ **我建议 (乙)，但这是你的决定** —— 它会动 `rootDir` 相关的构建假设。

| 臂 | 造什么 | 断言什么 |
|---|---|---|
| **正向** | 一条**多判据同时开火**的拒绝记录，消息形如 `[a.b] and [c.d]` | **两条都被记下**（不是只记 `a.b`） |

★ 为什么反向半边是必需的：`gateIdFromMessage` 的缺陷形态是**`.exec()` 只取第一个匹配**，
⇒ 一个**只记首条**的实现能通过全部正向断言，而它正是要被修掉的那个。
★ 语料基线（可复跑）：**18/384** 条卡点已受此缺陷之害（F13），修复后该分母应下降。

##### B0.2 展开规则 = **三类**（t26 F-2 的修法，★ 本行是 blocker 的落点）

**原句（v1/v2 都是）**：`只展开"活跃+异常"`。**t26 判定：这一句会折叠掉 `skippedAll`。**

**为什么必然发生（层级错配）**：`skippedAll` 是**位置级**字段
（`registry.ts:205`；`:199-205` 逐字「该位置【有判据、却一条都没跑】时的一句人话」「空位置【不产出】它」），
而"活跃 + 异常"是**判据级**的筛选条件 ⇒ **一个位置级的"什么都没发生"，在判据级规则里必然没有位置。**

**三种可能处置没有一种是对的**：

| 处置 | 后果 |
|---|---|
| 按 `ok === true` 判"不异常"⇒ 折叠 | ★ **重复本仓最贵的错**：`registry.ts:174-178` 的 t58 实测记录 integration/verification/review 三类任务**曾经永远报 ok**（`ok=true, evaluated=0, skipped=4, registered=4`） |
| 按 `ok === false` 判"异常"⇒ 合流 | `registry.ts:980-982` **逐字并列**三种 `ok:false` 成因且明令不许混：`blockers:[]` + `skippedAll:在场`（**这一步没被检查**）/ `blockers:[…]`（判据说有问题）/ `unmeasured:在场`（判据说测不了） |
| 规则里不提 | **取决于实现者** |

**⇒ 修正后的展开规则（三类，且"未检查"优先）**：

```
展开（按此优先级）：
  ① 未检查  ← ★ 新增。skippedAll 在场的位置，【强制展开】，优先级最高
  ② 异常    = blockers.length > 0 || unmeasured 在场 || skippedAll 在场
              （三者各自有符号，一一对应 registry.ts:980-982 的三种 ok:false）
  ③ 活跃    = 这一轮真的开火了的判据（verdict 非 skipped）
折叠：其余
```

**★ "折叠本身要留痕"**（F-2 的第二个要求）：六个插入点的**聚合行**上，
每个点除计数外必须带一个**"未检查"标记**，例如：

```
completion  ✓✓⊘⊘  (4 条，全部跳过 ⇒ 未检查)      ← ★ 折叠了，但聚合行看得见
contract    ✓✓✗
```

⇒ 理由：`skippedAll` 是**唯一"你不看就永远不会知道"**的一类；
即使明细被折叠，**聚合行也必须让它可见**。

**可复跑**：
```sh

sed -n '975,995p' src/gates/registry.ts    # 三种 ok:false 成因逐字并列
grep -c "skippedAll" src/tools/update-task.ts   # ⇒ 9 —— 生产路径已在用，证明它是承重字段
```

##### B0.3 ★ 为什么 A1 必须有第四类明细（"未检查"）

`skippedAll` 是**位置级**事实，因此它**不能**作为任何单条判据的明细项挂在"活跃"或"异常"里。
⇒ **A1 的出口必须有第四类**：`未检查位置[]`（每个元素 = 该位置 + `skippedAll` 的人话原文 + 计数）。
**只送前三次（聚合 / 活跃 / 异常）的 A1 与本节的展开规则不匹配** —— 两处必须同时改。
