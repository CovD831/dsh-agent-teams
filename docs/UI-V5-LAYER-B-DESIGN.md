## 2. ★★★ 三个方案（而它们的差别是"画什么"）

### 方案甲：★ **工位图**（办公室隐喻，最贴"公司的组织形式"）

```
┌─ 工作区 · agent-teams-dev ───────────────────────────┐
│                                                       │
│  ┌────────────┐  ┌────────────┐  ┌────────────┐      │
│  │  ▄▄▄▄▄     │  │  ▄▄▄▄▄     │  │  ▄▄▄▄▄     │      │
│  │  █ █ █     │  │  █ █ █     │  │  █ █ █     │      │  ← ★ 像素小人
│  │  ═════     │  │  ═════     │  │  ═════     │      │  ← ★ 工位（桌）
│  │ archaeol.  │  │ test-triage│  │ ui-dissect │      │
│  │ ● working  │  │ ○ idle     │  │ ● working  │      │  ← ★ 色彩 = 状态
│  │ t108       │  │ —          │  │ t111       │      │  ← ★ 在做什么
│  └────────────┘  └────────────┘  └────────────┘      │
│                                                       │
│  ★ 队长坐最前面（一个更大的工位）                      │
└───────────────────────────────────────────────────────┘
```

★ **优点**:直接对上「公司的组织形式」 + 「像游戏界面」
★★ **代价**:每个成员要占 ~100×110 px ⇒ **一屏放得下 4–6 个**

### 方案乙：★ **状态点阵**（更紧凑，信息密度高）

```
 archaeologist ●●○○○  t108 implementing      ← ★ 一行一人 + 5 个进度点
 test-triage   ●○○○○  idle
 ui-dissect    ●●●●○  t111 done
```
★ **优点**:紧凑（一屏能放 20+ 人）
★★ **代价**:**不像游戏界面** —— 而那正是用户要的

### 方案丙：★★ **两层**（甲为主，点开是乙的详情）

```
★ 默认:工位图（甲）—— 一眼看谁在忙
★★ 点一个工位 ⇒ 展开那一行的详情（任务 · 判据 · 轮次）
```

★ **优点**:兼顾"游戏感"与"信息密度"
★★ **代价**:要设计展开 —— 而**本仓已有先例**（`MemberRow` 的展开已实现）

## 3. ★★ 而我的建议：**丙**，而理由是**已有的东西能复用**

```

⇒ ★★★ 所以丙 = 【把 MemberRow 的那套搬到一个工位卡片里】

```
