# 纯搬运：逐符号计数与【分栏】（t94）

> **这条判据防的不是错误，是一份会系统性误导人的清单。**
> 判据本体在 `scripts/gate-pure-move.test.mjs` 的 `pureMoveVerdict()`。

---

## 1. 它是什么

出处：checkpoint-dev 在 t86 里的原话

> 「**「纯搬运」这个说法本身没有被任何判据核对过。**
>   ⇒ 能核对它的东西很便宜：**搬运前后逐符号计数**。」

而那条修正改变了它的**目的**：

```
旧理解：防一个粗心的搬运者           （= 人会犯错，所以要检查）
★ 新理解：防一份分不清"搬走了"与"坏了"的清单
        （= 清单把两类东西印成同一行，于是【谁照它做都会踩】）
```

⇒ ★ 所以本条判据要回答的不是"这个人搬全了吗"，
而是**这份读数能不能把「搬走了」与「坏了」分开**。

---

## 2. 它防的三次同源事故

| # | 事故 |
|---|---|
| t39 | 一次"纯搬运"把 `gitChangedPaths` 的接线**覆盖回旧版**（t41 接好的 worktree-aware 扫描变成没有调用方） |
| t70 | 拆分把 t69 的出口**覆盖回旧版** |
| t70 | ★ 同时丢了 4 组接线（见 §3） |

⇒ 共同形态：**一个动作自称"只是把东西挪了个地方"，而没有任何机制核对那句自称。**
⇒ 于是"搬运"成了唯一一种**可以静默丢内容**的重构。

---

## 3. ★★★ 核心：四态，而 `moved` 与 `lost` **分栏**

出处：t86 的原话（captain 采纳为本判据的核心）

> 「两者要不同形，必须让『读到的东西』与『声称的东西』**分栏报**：
>   · 「读错位置」= 那个东西**不存在于**它该在的地方 ⇒ 读数是"此处没有"
>   · 「行为回退」= 那个东西**存在于**它该在的地方而**没人用它**
>     ⇒ 读数是"此处有，而入口为空"
>   ★ 而失败清单把两者印成同一行字 —— 因为清单只报"红"，不报"**红在哪一格上**"。」

⇒ 本判据里的四态（**两两不同形**）：

```
ok           —— 计数不减少
moved        —— 在目标集合里少了，而在集合之外【找得到】
               ★ 读数："此处没有，别处有（在哪儿）"
lost         —— 在目标集合里少了，而【哪里都找不到】
               ★ 读数："此处没有，别处也没有"
not-a-move   —— 不适用（这不是一次搬运 / 判不了）
```

### 3.1 ★ 为什么分栏重要：两者的补救动作完全不同

```
moved ⇒ 去核"那次搬运该不该把它带走"        （可能完全正确）
lost  ⇒ ★ 去看那三个修复（今晚抹掉接线的那一种）
```

⇒ 印成一行，读的人必然把两者都当"丢了"去查 —— 而那正是 t86 说的「谁照它做都会踩」。

### 3.2 ★★ 而"这算不算坏"**不由判据回答**

```
判据给的：      【目标集合里少了，而别处有（在哪儿）】—— 那是可机械判定的
★ 而"这是不是坏"取决于【那次搬运的意图】 ⇒ 那是【给人看的结论行】，不是判据的裁决
```

⇒ 正确形态：**判据报 `moved`（附"别处有：`backtest.ts`"），而把"这算不算坏"留给人。**
★ 与 t81 那条（报告而不拦）是同一手法。

## 4. ★★★ 判据的两个【显式输入】

MEASURED（t94，本节是本任务最有价值的部分）：复核验收样本时发现，
**同一个改动可以给出三个都"看起来对"的读数** —— 因为它们量的是
**不同的集合 × 不同的词法口径**。

### 4.1 `inScope` —— 在【哪儿】数

```
captain 给我的： 在 src/tools/update-task.ts 那【一个文件】里数
我第一版错的：   在 src/tools/** 那【整个面】里数
```

★ 实测：`skippedAll` 在单文件里是 16，在那个面上是 24 —— **两个都"对"**。
⇒ 而差异的成因：**"在哪儿数"这一格，清单里没有写。**

★ 裁定（captain ③）：**目标集合 = `inScope` 声明的集合**。
理由不只是"契约原话"，而是：

```
inScope 【本来就是那次改动的声明】—— 而"纯搬运"是【关于那次改动】的说法
⇒ ★ 所以核对它的集合，也该是那次改动声明的集合。
```

### 4.2 词法口径 —— 【算不算】注释与字符串

```
captain 给我的：单文件 · 含注释  →  16
本判据的口径：  单文件 · 纯代码  →   6    ★ 契约说"符号 = 源码里的标识符"
```

★ 而这一格还包含一个**我当场被验收样本抓出来的错**：

> 我第一版把**模板字面量的 `${…}`** 当成字面量剥掉了。
> ⇒ `skippedAll` 从真实的 **13** 掉到 **2** ——
>   因为 4 处都在插值里（`${dispatchGates.skippedAll ?? …}`），
>   而**那些是真的符号使用**（它们会真的求值）。
> ⇒ ★ 而这在判据里是**危险方向**：少算会让 pre 变小 ⇒
>   一个**真的丢失**可能因为"两边都少算"而落进 `ok`。

⇒ 修法：模板串的 `${…}` **回到代码状态**（插值可嵌套），只有插值之外的文本才是字面量。

### 4.3 ★ 三个数字量的是三个东西（都已复核）

```
skippedAll 的 pre：

   16   →   单文件 · 含注释      （captain 最初给的）
    6   →   ★ 单文件 · 纯代码     （本判据的口径）
   24   →   tools 全体 · 纯代码   （我第一版量错的集合）
```

⇒ ★ **三个都"看起来对"。** 而那不是精度问题 —— **那正是本判据要防的东西。**
⇒ ★ 所以两者都是判据的**显式输入**，而不是隐含假设。

## 5. 合法差异 vs 丢失

| 变化 | 合法吗 | 为什么 |
|---|---|---|
| import 路径变了 | ✅ | 符号**没有消失**，只是它的来源换了个文件 |
| 行号变了 | ✅ | 按行号判会让它恒红（本队记账：**位置不是身份**） |
| 注释变了 | ✅ | 注释不是符号的载体 |
| 新增符号 | ✅ | 搬运**可以**顺带新增 |
| **某个标识符从 N 变成 0** | ❌ | **那就是丢了** |

⇒ ★ 口径是【计数不减少】，**不是**逐字节相同 ——
后者会把一切合法重构都判红，而**误报会教人忽略门禁**。

## 6. 验收样本：t70 那一次

★ 目标集合 = `src/tools/update-task.ts`（t70 那次搬运真正碰过的文件）；
词法口径 = 纯代码。

| 符号 | pre | post | ★ 分栏 | 别处找得到吗 |
|---|---|---|---|---|
| `parseKnownBaselineFailures` | 3 | 0 | **`moved`** | ✅ `src/gates/completion/backtest.ts` |
| `baselineAbsent` | 2 | 0 | **`moved`** | ✅ `backtest.ts`（4 处） |
| `knownBaselineFailures` | 3 | 0 | **`moved`** | ✅ `backtest.ts`（5 处） |
| `skippedAll` | 6 | 0 | **`moved`** | ✅ `registry.ts` / `entities.ts` |

```
★ 判据对那一次报出【exactly 那 4 个】（多报与少报都让它在真实事故上不可用）
★ 而那 4 个都落 moved —— 附"别处有：哪个文件"
★ 总减少数：104 个符号（★ t70 把 264 行搬出了那个文件）
```

### 6.1 ★★ 而"那 4 个都落 lost"这个断言我**没有**写

★ 因为实测它们是 `moved`（在别处还找得到）。
⇒ 写一个与实测相反的上界，会让这条判据**在它唯一的真实样本上恒红**，
而那时读的人会去**改判据**（而不是去看那份清单）。

> ★ **"恒红"比"恒真"更危险。**

★ 而我第一版真的这么错过一次：我写了 `shrunk.length <= 8`，
理由是"t70 只丢了 4 个符号"——
★ 而那 4 个是**点名的**那 4 个接线，**不是 t70 丢的全部**。
⇒ 那是**把一个子集当成了全集**。

## 7. 定向突变（实测）

```
★ 把 moved/lost 的【分栏合并】（两栏都归 lost）
  ⇒ ★ 臂 1 红（4/5）
  ⇒ 还原后 5/5
```

### 7.1 ★★ 而这里我第一版又错了一次（值得单独记）

```
我第一版写的是 `assert.notEqual(inMoved, inLost)`（"恰好落一栏"）。
⇒ 合并两栏之后：inMoved=false, inLost=true ⇒ ★ 那条断言【照样成立】⇒ 5/5 全绿。
⇒ ★ 一条"恰好落一栏"的断言【看不见"哪一栏"】——
  而"哪一栏"正是这条判据的【全部价值】。
⇒ 改成钉【方向】：必须落 moved、不许落 lost、且必须点名 foundIn。
```

## 8. 已知边界

```
1. ★ "这是不是一次搬运"【不可机械判定】（那是意图）。
   ⇒ 本判据的口径是：调用方【声称】是搬运，而判据做一次**便宜的合理性核对**
     （没有 inScope / 搬运前为空 ⇒ not-a-move）。
   ★ 而 `not-a-move` **不许**被并进 ok（那是"没测到并进通过"）。

2. ★ 第三栏（`outside`）缺席 ⇒ 减少的那些落 `unclassified`。
   ★ 而它**不是** `lost` —— 把"我没看别处"读成"别处也没有"，
     就是**把没测到并进结论**。

3. ★ 词法口径是"剥注释 + 模板串插值算代码"，不是完整词法分析。
   若将来需要更精确，那要一个真的 parser ——
   而那件事**不该**由这条判据自己做（它会变成不可测的解释器）。

4. ★ 它只报读数，不拦任何流程（与 t81 同一手法）。
```
