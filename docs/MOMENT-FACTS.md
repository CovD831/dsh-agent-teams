# 写在某个时刻的事实（t51）

> **一句话**：一个写在某个时刻的事实，在没有被复核的情况下，继续被当成本刻的事实。
>
> 这份文件把它收敛成**五个长相**，而每个长相配一条**判别动作**。
> ★ 判别动作才是这份文件的价值 —— 分类只是索引，动作才是能用出去的东西。
>
> **它和台账的关系**：`.agent-teams/frictions/` 是**原始记录**（可重放的现场），
> 这份文件是**归纳**（从一个时刻的材料里抽出的形状）。
> ⇒ 台账丢了不能重算；这份文件丢了可以**从台账重写**。
> ⇒ 所以每一节都指名台账条目，而不是复述它 —— 复述会变成第 11 份事实。

---

## 0. 为什么会有这份文件

2026-10-07 的 13 个任务里，同一个形状反复出现。它不在任何一个判据里，
而在**判据、夹具、契约、文档、快照**全都共享的那个动作上：

```
写下（或读入）一个事实  →  它当时为真  →  之后没有人再回头问它  →  它被当成本刻的事实
```

★ 而它最危险的地方是：**它让"我读对了东西"与"东西还是那个东西"变成两个都没人检查的前提。**
一次 `grep`、一个 `inScope`、一份 golden、一条 stamp —— 它们都长得像"读数"，
所以看起来**自动就是最新的**。

**今天实测的六个现场**（每个都指向具体任务）：

| # | 现场 | 写下的时刻 | 读到它的时刻 | 差在哪 |
|---|---|---|---|---|
| ① | t44 的 `verify` 字段指向**已改名**的文件 | 契约写下时那个路径存在 | 改名之后 | 路径名变了，契约没变 |
| ② | t42 的 `inScope` 用**拆分前**的写法 | 拆分前 | 拆分后 | 目标文件落在真空（谁都不拥有它） |
| ③ | t42 的 golden 冻结了**建它那一刻**的定义 | 生成时 | 每次改动之后 | 只能手改，而手改会腐烂 |
| ④ | t38 一个信号在 **39 条**语料上成立、在 **44 条**上失效 | 39 条时 | 44 条时 | 语料长大了，信号没被反例检验过 |
| ⑤ | t48 三条夹具在**旧位置**找已搬走的东西 | 拆分前 | 拆分后 | 读数的**仪器**指向了旧地址 |
| ⑥ | golden 没有**重新生成的路径** | 手写那一刻 | 下一次需要改它时 | "手改"与"重新生成"在今天同形 |

★ ⑥ 与 ③ 是同一件事的两端：**③ 是症状（冻结的定义），⑥ 是成因（没有再生路径）。**
只在 ③ 上修（把那一格改对）会让它下个月再犯一次；修 ⑥（给它一个 `--check` 与再生器）
才改变**下一次**。这条区别来自 `fe9de34` 的提交信息，原文：

> 「手改与重新生成**今天看起来一样**：两种方式都是四个键落进那一格。
> 它们**在下一次改动时**才分岔。手改的变成一份"必须有人记得保持它为真"的声明面；
> 重新生成的则始终派生自活的注册表。」

## 1. 五个长相

★ 下面每一节都是同一个结构：**长相 → 台账条目 → 判别动作 → 今天的一次实测**。
"判别动作"是可以照着问出口的一句话；没有它，这一节就只是分类。

---

### 长相一：读错位置的出口

**长相**：读数在场、类型对、值也读得出来 —— **只是它不是读者以为的那个位置报的。**
最坏的形式是"字段在场"被当成"那个功能在工作"。

| | |
|---|---|
| **台账** | `f-0027`（检测器被用在**错误的进程**上：命令行读不到插件进程的内部状态）<br>`f-0029`（把**位置**当成身份：夹具硬编码了 `src/tools.ts` 的行号）<br>`f-0026`（检测器缺一维：`current` 不能证明"进程是新的"，而它被用来证明了两次） |
| **判别动作** | ★ **「这个读数，在什么条件下会与它声称的对象不同？」**<br>若答不出任何条件 ⇒ 它要么恒真，要么**根本没在读那个对象**。 |

**今天的一次实测（`5b71204`）**：拆分之后，三条夹具**仍在旧文件里**找已经搬进
`src/tools/*` 的字符串。它们的红长得**与"有人把重构改坏了"完全一样** ——
其中一条的用例名甚至就叫"父版本必须落进耐久态"。原文说得比我准：

> 「一个**读数仪器指向了搬走的位置**的夹具，与一个**缺陷真的还在**的夹具，
> 从"红"本身**分不出来**。这两条臂都会接受"缺陷回来了"作为解释。」

⇒ 而它给这条长相配的动作，机械形式是**一条"不许为空"的断言**：

> 「其中一条恰好防住了这件事：一条断言**接线点普查不许为空**的臂 ——
> 因为"空集的每个元素都合法"是**恒真**的。当读数变陈旧时它产出零个点，
> 而那条断言把一次静默的通过变成了红。」

★ 这正是长相一与长相四（样本上的巧合）在**动作**上相通的地方：
问"它可能不可读吗"的最强形式，是**断言它非空**。

---

### 长相二：读了过期的来源

**长相**：读数的**来源**是旧的，而读数本身完全正确 —— 它忠实反映了**那个旧来源**。
它与长相一的差别：长相一读错了**地方**，这里读对了地方、只是**那个地方过期了**。

| | |
|---|---|
| **台账** | `f-0025`（ESM 静态绑定：「每次调用时求值」不精确）<br>`f-0026`（stamp 缺"构建时的 git 提交"一维）<br>`f-0030`（`reload != restart`：一个动作的**名字**暗示了它做的事，而它做的不是那件事）<br>`f-0021`（两个缺口互相锁死：旧模块 ⇒ 任务冻住 ⇒ 重载闸门永不满足） |
| **判别动作** | ★ **「这条读数，来自哪里？而那个来源，凭什么还是最新的？」**<br>且"它来自哪里"与"它凭什么新"是**两个问题，缺一不可**：<br>　· 来源是内存／缓存／上次构建时写下的标记 ⇒ 读过期来源的条件已经成立；<br>　· 而"最新"若**没有任何一维读数**在证明 ⇒ 它只是被假定为最新。<br>⇒ `f-0026` 的 `stamp` 正是**只答得出前半句**：它说了"构建于何时"，答不出"构建自哪个提交" —— 而它被用来证明了两次。 |

**今天的一次实测（`1ae74a6` / t42）**：`stamp` 原本只有一个"构建于何时"，
于是 `current` 不能证明"进程是新的" —— 而它**被用来证明了两次**（`f-0026`）。
修法是给 stamp **加一维**：构建时的 git 提交。原文的判据因此变成一句可判的话：

> 「captain 提交后 HEAD 前进而 stamp 未更新 ⇒ 检测器报 `{status:'stale', …}`」

⇒ 这条长相的动作，机械形式是：**问"谁在读它"与"它凭什么新"是两个不同的问题**，
  而**两者都要有出口**。`f-0027` 记的正是只有后者而没有前者：

> 「t23 的 WIRING GAP：`moduleFreshness` 还没接到任何工具出口」
> ⇒ 检测器**算出来了**，而**没有任何地方读得到它**。

★ 一条算得出、却读不到的读数，与没有这条读数**在行为上相同**，但在文档上不同 ——
所以它必须出现在这份归纳里。

### 长相三：契约字段过期

**长相**：`inScope` / `verify` / `golden` 这些**契约字段**在写下的那一刻为真。
之后世界变了（文件改名、代码拆分、schema 增长），而**契约不会自己重读**。
★ 后果不是"判据报错"，而是**目标文件落在真空**：谁都不再拥有它。

| | |
|---|---|
| **台账** | `f-0031`（金快照的作用被证伪了一次：它不是防作弊，而是**防误判**）<br>`f-0032`（拆分修出的三个真缺陷，最危险的那个**伪装成"我没能测量"**）<br>`f-0035`…`f-0058` 里大量 `changedPaths` / `completion gate could not measure` 的拒绝记录 |
| **判别动作** | ★ **「这条读数，在没有那个缺陷时还成立吗？」**<br>★ 并追加一问：**「那它现在为真，是因为事实为真，还是因为没人再看过它？」** |

**今天的一次实测（t42 契约本身）**：t42 的 `inScope` 用的是**拆分前**的写法。
拆分之后，那些路径里的目标**落进了真空** —— 不是"判据误报"，而是**没有任何判据在管它**。
⇒ 这解释了为什么它同时撞上两次"契约冲突"，而两次根因**同一个**：

> 「**契约里的东西，会因别人的重构而失效。**」

**另一条实测（t44 的 `verify` 字段）**：契约的 `verify` 指向一个**已改名**的文件。
★ 而它和长相一不同：这里没有谁读错位置 —— 只是**写下的那一刻过去了**。

### 长相四：样本上的巧合

**长相**：一个信号在一批样本上"成立" —— 而那批样本**恰好**都是它想命中的形状。
换一批样本就失效。★ 它不是"信号写错了"，而是**信号从来没有被反例检验过**。

| | |
|---|---|
| **台账** | `f-0034`（独立验证**证伪**了「原子化判据」：它判的是**字符串末字符**，不是那件事） |
| **判别动作** | ★ **「什么样本会证伪这个信号？」**<br>**答不出来 = 它还没被检验过。**（不是"它是对的"） |

**今天的一次实测（t38 → t43）**：t38 最终只用"`inScope` 里有目录条目"这一个信号，
在 **44 条**语料上 `ok 42 / blocked 2`，而那 2 条正是已知不原子的 —— **零误报**。

★ 而独立验证（t43，`f-0034`）用一个**同形反例**把它分开了：

```
['src/registry.ts', 'src/index.ts']            ⇒ ok
['src/registry.ts', 'src/index.ts', 'src/']    ⇒ blocked     ← 同一件工作，多一个尾斜杠
['src/a.ts']          ⇒ ok
['src/']              ⇒ blocked                              ← 信息更少，判定更确定
```

⇒ 源码只做 `path.trim().endsWith('/')`。**它判的是字符串的最后一个字符。**
而它的"零误报"是**语料的巧合**：那 2 条语料恰好真的要新建目录
（`t30`/`t39` 的 `inScope` 同时写了 `'src/tools.ts'` 与 `'src/tools/'`，而该目录不存在）。

★ 这条长相与长相一、二的关键差别：**它的动作不需要读代码，只需要换样本。**
⇒ 所以"问什么样本会证伪它"是最省的一条动作，也是最容易被跳过的一条
（因为**当下的绿灯就是它被跳过的理由**）。

### 长相五：代理读数

**长相**：读数**代理**了真实对象 —— 两者通常同步，而**不同步时读数仍然会变**。
于是在"我关心的事没发生"时它照样会红／会绿。

| | |
|---|---|
| **台账** | `f-0022`（夹具造出的缺陷与产品缺陷**在返回值上同形**：同一现象、三次不同成因）<br>`f-0029`（把位置当成身份：行号是**代理**，不是身份） |
| **判别动作** | ★ **「这个读数变化，是否只可能由我关心的事引起？」**<br>若还有别的成因能引起同样的变化 ⇒ 它是一条**代理读数**，而它的红／绿都不指向结论。 |

**今天的一次实测（t49）**：注释变了而**控制流没变**，臂却红了 ——
因为臂读的是**源码文本**（代理），而它关心的是**行为**（对象）。
★ 这不是"臂写错了"：读源码是**唯一**能在不重载进程的前提下读行为的办法。
⇒ 正确处置不是删掉它，而是**给这条代理配一条判别动作**：

```
臂红了 ⇒ 先问「控制流变了吗？」而不是「谁改坏了？」
```

**同一长相的另一次实测（`f-0022`，我今天亲自踩了三次）**：
`kind:'quality'` 不在 `TASK_KINDS`、`verify:['grep -qx 7']` 静态面抓不到、
`verify:['   ']` 被 `normalizeBlankOptionalTaskFields` **整个删掉** ——
三种成因，**同一种症状**（"这句调用没抛错／抛错了"）。
⇒ 我当时三次都差点报成"那个缺陷回来了"。

## 2. 五个长相在动作上的关系

★ 分类只有索引价值。**这四条动作才是能用出去的东西**，而它们覆盖五个长相的方式是交错的：

| 判别动作 | 一·读错位置 | 二·过期来源 | 三·契约字段 | 四·样本巧合 | 五·代理读数 |
|---|:--:|:--:|:--:|:--:|:--:|
| 「在什么条件下会与它声称的对象不同？」 | ● | ○ | | | ● |
| 「它来自哪里？凭什么还是最新的？」 | ○ | ● | ● | | |
| 「什么样本会证伪它？」 | ○ | | | ● | ● |

（● 主要适用　○ 也适用）

★ 而它们有一个**共同的机械形式**，这是这份文件最想说的一句：

> **给每条读数配一条"它在什么情况下会说谎"的断言。**
> 通常那就是"不许为空"、"不许恒真"、"换一个样本" —— 而它们都是**断言**，
> 不是纪律。

## 3. 为什么它值得单独成文（而不是留在台账里）

台账（`.agent-teams/frictions/`）的纪律是**记录 ≠ 结论**：记录要**可重放**。
而"可重放"意味着它**必须保留当时的现场** —— 于是它**不归纳**，也不该归纳。

这份文件做的是相反的事：**从现场里抽出形状**，代价是它**不可重放**。
⇒ 两者的分工：

```
台账        = 原始现象（可重放，不归纳）        ← 丢了不能重算
这份文件    = 归纳（不可重放，必须可追溯）      ← 丢了可以从台账重写
```

★ 所以每一条长相都必须**指向 f-XXXX**：一个不指向现场的归纳，与一次猜测同形。

## 4. ★ 这份文件本身也会过期

**它不是一份"到此为止都成立"的清单。** 它是**到 2026-10-07 这一刻**为止的归纳，
而它描述的正是"写下的那一刻之后会怎样" —— **⇒ 它自己也会变成那样。**

具体的过期方式，它自己就构成一类：

| 它可能怎么过期 | 这次该问的动作 |
|---|---|
| 五个长相里某一个被**修好了**（信号被替换、再生路径落地） | 「它现在还成立吗？」 |
| 出现**第六个**长相（今天的样本里没有） | ★ 「我这份归纳的样本是什么？什么样本会证伪**它**？」 |
| 台账条目被关闭／改号 | 逐条复核 `f-XXXX` 仍指向同一件事 |
| 判别动作被**绕过**（问了但没有出口） | 「问出这个动作之后，**谁**因此改了什么？」 |

★ 最后一条最要紧，也最容易失效：**一条被问过、却没有改变任何东西的判别动作，与没问过同形。**
⇒ 所以这份文件不宣称它覆盖了全部，也不宣称它已经是机制 ——
**它现在是一份归纳；要变成机制，得有人把上面的动作写成断言。**
