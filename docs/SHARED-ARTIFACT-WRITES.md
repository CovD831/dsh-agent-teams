# 共享产物在并发下的序关系（t68）

> **这是一条【判据】的说明书。** 判据本体在
> `scripts/gate-shared-artifact-writes.test.mjs`，本文说清它判什么、
> 为什么这么判、以及它的边界在哪。
>
> ★ 它**不碰 `src/` 与 `lib/`**：它只扫 `scripts/` 下的源码文本。

---

## 1. 它防的是什么失效

> **两个动作在同一个共享资源上没有序关系。**

★ 而它是**今晚实测到的三次** —— 而每次的位置都不同：

| # | 位置 | 症状（都是实测） |
|---|---|---|
| ① | **t56 的夹具**在【共享的 `lib/`】上跑 `rm -rf lib` 来模拟旧实现 | 那一步一旦失败或被打断，就把 `lib/` 留成残缺 ⇒ 此后 **49 个夹具**报 `ERR_MODULE_NOT_FOUND` |
| ② | **clean-build 的 carry-forward**：`exists(from)` 通过之后、`copyFile` 之前 | 那个文件可能已被**另一次并发构建**删掉 ⇒ ENOENT ⇒ 整个 build 崩 |
| ③ | **gate-stale-module** 污染共享 `lib/git-artifact-stamp.json`，并在 `finally` 里还原 | 并发时那个还原会写回**过期值** ⇒ 后续 **19 条臂**一起红 |

### ★★ 而 ③ 最隐蔽

```
它【有】还原逻辑 —— 所以它看起来是【谨慎的】。
而那个还原正是让它更坏的东西：
    它用一份【过期快照】覆盖了别人刚写的新值。

⇒ ★ "意图是恢复" 不改变 "它写了共享资源" 这件事。
```

### ★★★ 三次的共同点

```
单个动作看起来都对，而它们之间【没有序】。
```

而三次"换位置"的方式都不同形：

```
· 读的人在 rm 窗口里读          （①）
· copy 的人在窗口里 copy        （②）
· 写回的人用【过期的快照】覆盖    （③）
```

## 2. 判据的形状（可机械判定）

```
扫全部夹具与脚本，找出【写共享产物】的地方
⇒ 对每一个，断言它【要么不写共享资源，要么写的是一个私有副本】
```

★ "可判定"在这里是具体的：**看它写的那个路径是不是在共享树里。**

### 2.1 共享树的定义（操作性的）

> **被多个测试（或测试与被测代码）都读的东西。**

| 共享根 | 谁读它 |
|---|---|
| `lib/` | 700+ 夹具从它 import |
| `lib/git-artifact-stamp.json` | `moduleFreshness()` 读它（③ 的受害者） |
| `.agent-teams/` | 团队状态，多个夹具读它 |

★ **不**包括 `src/`（夹具不写它）、`node_modules/`（装完就不动）。

---

## 3. ★ 四态（而这四态不得合并）

```
private  —— 写的是私有副本（tmpdir / mkdtemp 出来的）   ⇒ 合格
none     —— 根本没写（只读）                            ⇒ 合格
shared   —— 直接在共享树上写                            ⇒ blocked（除非在白名单）
unknown  —— ★ 路径动态构造、静态看不出来                ⇒ 第四态，不得并进任何一态
```

★★ **为什么 `unknown` 必须单独存在**：

```
并进"合格"  ⇒ 把【没测到】并进【通过】（本队最老的记账）
并进"违规"  ⇒ 在每一个 writeFileSync(someVar) 上误报
             ⇒ 而误报会教人忽略门禁，与漏报同样有害
```

---

## 4. ★★ 反向半边：白名单必须有理由

**真的需要写共享资源的**（构建链本身）必须进白名单，且每一条要**说明理由** ——
不是"全都拦"。

| 白名单条目 | 理由（结构性，不是"我觉得"） |
|---|---|
| `scripts/clean-build.mjs` | ★ 它就是构建的**原子替换**本身：把 `lib.tmp` 换成 `lib/`。它写的时刻是**唯一允许**改 `lib/` 的时刻，而它用两次 `rename` 把窗口压到微秒级。⇒ 它是"谁有权写共享产物"这个问题的**答案**，不是它的反例。 |
| `scripts/git-artifacts.mjs` | ★ 它是**构建的最后一步**：给构建产物打指纹（`--write`）。与 clean-build 同属构建链，且只在 build 末尾跑一次。 |

### 4.1 ★★★ 而实例 ③ **不在**白名单里

```
它是【待修的存量】，而白名单是【有结构性理由的例外】。
⇒ 把两者混起来，就是用白名单把一个缺陷【永久合法化】。
```

★ 而实例 ③ 与 `git-artifacts.mjs` 的区别是决定性的：

```
git-artifacts.mjs  在 build 的【末尾】跑一次，写的是【刚刚构建出来的】那棵树的值
实例 ③             在【任意时刻】写，且写回的是一份【过期快照】
```

## 5. 分类器的三次修正（每一次都由臂当场打回）

★ 值得单独记，因为它们都是**"看起来对"的写法**：

| 版本 | 写法 | 错在哪 | 被哪条臂抓住 |
|---|---|---|---|
| 一 | 拿**整行**匹配共享名字 | `writeFileSync(backup, readFileSync(BUILT_GATE,…))` 被误报 —— ★ 而那一行恰恰是本仓**正确的隔离写法**（把共享产物备份到私有路径） | 臂 3 |
| 二 | 只取"第一个参数"或"最后一个参数" | `cpSync(LIB, join(tree,'lib'), {recursive:true})` 的"最后一个"是 `{recursive:true}`；`execFileSync('rm', ['-rf', LIB])` 的第一个是 `'rm'`（命令名） | 臂 1 / 臂 3 |
| 三 | ★ 按**动作的语义**取"会被写到的那个位置" | —— | （通过） |

### 5.1 ★★ 另一个"失明"的写法（同一批修正里发现的）

```
第一版只认【直接调用】（writeFileSync / rmSync / …）
⇒ 而 t56 那次事故恰好是 execFileSync('rm', ['-rf', LIB]) —— 【shell 那一族】
⇒ 一个"只认直接调用"的扫描器会对最危险的那种写法【失明】，
   而它失明的方式很隐蔽：那一行会被判成"不是写动作"而【根本不进入分类】。
```

### 5.2 ★ 还有一个真陷阱：共享根与写调用**常常不在同一行**

```js
const LIB = join(ROOT, 'lib')        // 第 55 行
...
execFileSync('rm', ['-rf', LIB])     // 第 80 行 —— 只扫当前行的话判成 unknown
```

⇒ 修法：先收集文件里**绑定了共享根的标识符**（共享别名），再在写行里找它们。

## 6. 定向突变：两个方向，而失败签名【不同】

| 突变 | 内容 | 结果 |
|---|---|---|
| **A** | 往一个夹具里**注入**一条共享写入（实例 ① 的形状） | 臂 **4** 红 ｜ 臂 1/2/3/5 绿 |
| **B** | 把 copy 的**源**当成它的目标（＝过度拦截，误报正确的隔离写法） | 臂 **3** 红 · 臂 **4** 红 ｜ 臂 1/2/5 绿 |

★★ **签名不同** ⇒ "该拦的拦得住"（A）与"不该拦的不拦"（B）各自被不同的臂抓住。

## 7. 它只记账，不修

★ 契约原话：「它只记账不修（一次性全修会让判据从"读数"变成"门禁"，
而那是本队一直在防的）。」

⇒ 所以：

```
· 存量清单（KNOWN_SHARED）**如实列出**当前全部的共享写入，每一条带成因
· 任何【新增】的共享写入 ⇒ 红（判法是精确相等，不是"不超过 N"）
· 而"减少"也要有人来改那一行 ⇒ 于是那张清单是一次【要有人说话的】变更
```

★ 为什么是"精确相等"而不是"不超过 N"：

```
"不超过 N"   ⇒ 存量会慢慢长（每次加一个都不到线）
"精确相等"   ⇒ 任何变化都要有人说话
```

## 8. 已知边界（不假装它能做更多）

1. **它是静态文本扫描，不是执行追踪** ——
   一个"运行时才算出来"的目标会落 `unknown`（★ 而那是第四态，不是合格）。
2. **它判的是"写了没有"，不是"写的时候有没有序"** ——
   一个夹具完全可以合法地写私有副本、再原子换进共享树（`clean-build` 就是），
   而本判据**不评判那个换法对不对**（那是 `docs/SHARED-ARTIFACT-WRITES.md`
   之外的事，见 t56 的设计）。
3. **`unknown` 只被计数、不被拦截** ——
   那是刻意的：拦 `unknown` 会在大量正常写法上误报。
   ⇒ ★ 而它的代价如实说明：**一个把目标藏进变量的共享写入会被漏掉。**
   要覆盖那一类，需要的是执行期追踪，不是这份静态判据。
4. **白名单是手写的** —— 而它被臂 5 审着：每条必须有理由、必须指向存在的文件、
   且实例 ③ 不许进去。
