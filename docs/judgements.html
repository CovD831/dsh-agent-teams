「停在可恢复的中间态」让掉线无害 —— 而它的判据是「重做一遍的代价」

★ 什么会证伪它

★ 反例：若一个任务的中间态【不可恢复】（例如它正在写一个多文件重构的中途、而 worktree 只落了一半），那掉线就会损失工作。⇒ 所以这条判据【只对设计成可恢复的任务成立】，不是「掉线无害」的一般结论。

它从哪来

怎么复用
派任何长任务时：问「若它此刻掉线，我损失什么？」—— 若答案不是「重跑一遍」，就该在派工前把它切成可恢复的步。

「尾斜杠对照对」—— 用同一件工作的两种写法，把「形状检查」与「真判断」分开

★ 什么会证伪它

★ 反例：若两份输入【不是同一件工作】的两种写法，对照就不成立。所以构造时必须确认「两边做的事逐项相同」，而那正是它做的（只差一个字符）。

它从哪来
t43（verifier6 独立验证 t38）
判据断言 inScope 里有【目录条目】= 会新建目录 ⇒ 不原子。而它只做 path.trim().endsWith('/')。verifier6 构造：['src/registry.ts','src/index.ts'] ⇒ ok，而加一个 'src/' ⇒ blocked —— 两边工作完全相同。更尖锐：['src/a.ts'] ⇒ ok 而 ['src/'] ⇒ blocked（信息更少却判定更确定）。
怎么复用
任何「看起来能分开」的信号，都可以用【同一件工作的两种写法】去试它 ⇒ 若两者不同裁，它判的是写法。

「手改与重新生成，今天看起来一样，下一次才分岔」

★ 什么会证伪它

★ 反例：若那个产物【本来就是手工维护的】（例如一份人写的设计文档），那它没有「重新生成」这个选项 ⇒ 这条判据不适用。⇒ 它只对【派生物】成立。

它从哪来
t42（integrator6）
golden 快照的 deployment 一格需要加四格。captain 说「我来手工更新那一格」，而 integrator6 更正：手工改与重新生成，在【当下】看起来一样（都得把那四格放进去），在【下一次】不同形。
怎么复用
面对一个派生产物：问「它是从什么生成的？那条路径写下来了吗？」—— 若没写下来，那它其实已经是手工维护的了。

突变要打在「被测模块自己」的行上，不要打在它依赖的常量表上 —— 否则你测的是 import 缓存，不是行为

★ 什么会证伪它

若那个常量表就在被测模块自己里（不跨模块），这条不适用 —— 因为那时没有两个实例。判据是「针脚所在的模块，与断言读的模块，是不是同一个实例」。

它从哪来
t55（checkpoint-dev）
夹具 freshState 只 bust lib/state.js，而它静态 import 的 ./types.js 是裸路径 ⇒ 与夹具 ?tag 加载的 lib/types.js?tag 是两个模块实例。探针实测：mutant.DELIVERY_OUTCOMES 看到的是突变体，而 mutant.buildDeliveryRecord 用的仍是旧的 ⇒ 断言红，而报告会读作「突变没打红」。方向恰好相反。
怎么复用
写任何跨模块突变的夹具时：先问「这个突变真的施加到被测模块实例上了吗？」验证方法是让探针同时读两个模块并比对。
状态含义
它经得住目前的反例 —— 而那不等于它被证明了。
备注
  • 修法不是「再 bust 一层」（每加一层依赖就再失效一次），而是把针脚放在被测模块自己那一行上。
  • 与 t53 同族：t53 是「静态 import JSON 被内联 ⇒ 改数据不生效」，t55 是「跨模块实例的常量 ⇒ 突变不生效」。
  • 共同形态：我改的那个，与它测的那个，是不是同一个。
