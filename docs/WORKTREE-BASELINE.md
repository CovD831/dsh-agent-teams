# worktree 的基线过期

> **读数**：`worktreeBaselineFreshness(workspace)` · `describeBaselineFreshness(freshness)`
> **判据**：`scripts/worktree-baseline-freshness.test.mjs`
> **一句话**：**我的检出比主干旧吗？**

---

## 一、它修的是什么（两个成员各自撞到，而两次都不是他们的错）

| | 检出里的基线 | 后果 |
|---|---|---|
| **t72** | 没有 t69 的修复 | 它读到 **28 条红**，而主树只有 **4 条** |
| **t70** | 没有 t69 修的那个「空理由」 | 它报了一条**已经修好**的缺口 |

⇒ 两次都是「**切分支的时点早于某个修复**」，而两次都让成员在
**不存在的问题**上花时间去查。

---

## 二、★ 而这不是偶发 —— 它是本仓的常态

```
[基线读数] 本仓 46 个 worktree：current 1 · behind 45 · undecidable 0
  落后示例：task-t13(-61) · task-t14(-61) · task-t16(-60) · task-t19(-56) · task-t24(-44)
```

MEASURED（2026-10-08，`scripts/worktree-baseline-freshness.test.mjs` 臂 8 每次运行都打印）：

> **46 个检出里 45 个落后，最深的落后 61 个提交。**

★ 一个落后 61 个提交的检出，会读到**一整套已经不存在**的失败 ——
而**没有任何东西**在被读之前告诉那个成员这件事。

---

## 三、★★ 形态：worktree 相对主干的时序，没有任何东西在读

它与「**已提交但未并入主树**那一段在观察面里不存在」是**同族** ——
同一个量的两个方向：

```
① 让【过时】可读（本任务）    : 我的基线比主干旧吗
② 让【已提交】可见（另一条）  : 我提交了而主干还没有的东西，算不算改动
⇒ 共同形态：worktree 与主干之间的【差】，没有任何东西在看。
```

★ 而 **②** 是那条让「先提交再交终态」在结构上不可达的缺口
（今晚拦了 t31 / t39 / t68 / t71 四次）。

---

## 四、★★ 设计问题：为什么选 ①，而**不是** ②

三条路：

```
① 建 worktree 时记录基线 commit，交终态时检查它是否落后于主干
② 让观察面读 `git diff main...HEAD`（同时解决"已提交但未并入"）
③ 两者都做
```

### ★ 而 ② 在本仓**测的不是那件事**（实测，不是推理）

在一个真实的落后 worktree（`task-t13`，落后 61）上：

| 命令 | 结果 | 它问的是什么 |
|---|---|---|
| `git diff --name-only main...HEAD` | **0 个文件** | 「**本分支**相对分叉点加了什么」 |
| `git diff --name-only main..HEAD` | 219 个文件 | 「主干有而我没有的**文件**」 |
| `git rev-list --count HEAD..main` | **61** | 「主干有而我没有的**提交数**」 |

★ **三点式看不见过期**：落后的 worktree 往往**一个字都没提交**
（它在脏工作树里干活）⇒ 它报 `0`。
⇒ 而那个 `0` 与「完全同步」的 `0` **同形**。

★ **两点式方向是反的**：它列的是「主干有而我没有」的改动。
⇒ 把它塞进**观察面**，会把**别人的**改动算成本次任务的改动 ——
而那正是 `dispatch.changed-paths` 存在的理由要防的事。

### ⇒ 结论

> **② 把两个不同的问句混成了一个名字。**
> 过期的正确读数是 `HEAD..main` —— 它属于**这里**（一条可读的读数），
> **不属于**观察面。而"已提交可见"要在观察面上做，那在 `src/tools.ts`（本任务域外）。

★ 所以本任务做 **①**，并把 **②** 写成**已知边界**（第八节），而不是假装覆盖它。

---

## 五、三态，且三者不同形

| 读数 | 何时 | 补救动作 |
|---|---|---|
| `current` | 差 **0** 个提交（基线 == 主干尖端） | 什么都不用做 |
| `behind` | 落后 **N** 个（附 N 与主干尖端） | 重切分支 / 并入主干 |
| `undecidable` | 读不到（不是仓库 / 没有 HEAD / 没有主干引用） | **去把 git 接上** |

★ **前两者都"读到了"，第三者"没读到"** —— 而它们的补救动作完全不同。
★ 而 `undecidable` **绝不**读成 `current`：那是本队记账最久的那条合流
（把「没能测量」读成「是最新的」）。

---

## 六、★ 两个量必须分开

```
「我落后主干多少」  ≠  「我自己提交了多少」
```

我提交了 2 个、而主干前进了 3 个 ⇒ **我落后 3 个**（而那 2 个是我的）。

★ 把两者合成一个"差异数"，会让「我在主干之前」与「我在主干之后」**同形**。
⇒ 所以读数只数 `HEAD..main`（主干有而我没有的），**不含**自己提交的那些 ——
判据臂 6 钉住这一条。

---

## 七、臂与它们的定向突变

| 臂 | 它钉什么 |
|---|---|
| 1 | **反向半边**：正常切出的 worktree ⇒ `current`（不许恒报过期） |
| **2** | **核心**：主干前进而检出没动 ⇒ `behind`，且给出落后几个 |
| 3 | 落后的**信息**要说得出口（含后果，不只是数字） |
| 4 | 读不到 ⇒ `undecidable`，且与另两态不同形 |
| 5 | 三态两两不同形 |
| 6 | 落后数只算主干有而我没有的（自己的提交不许混进来） |
| **7** | **突变臂**：基线改成旧的 ⇒ 必须从 `current` 翻成 `behind` |
| **8** | **真实读数**：对本仓 46 个 worktree 跑一次并如实报出（45 behind / 1 current） |

### 两个定向突变（都实测打红）

```
A 恒报 current                      ⇒ 臂 2/3/5/6/7 红
B 方向反过来（读 main..HEAD）        ⇒ 臂 2/3/5/6/7 红
```

★ **B 尤其重要**：它正是第四节那个「② 与 ① 混成一个名字」的机械形式 ——
方向一反，"我落后多少"就变成了"主干有多少文件我没有"，
而那个数在完全同步的检出上**也是 0**。

---

## 八、★ 已知边界（本任务**不**覆盖的）

```
① 它【只报】过期，不改任何东西。
   ★ 重切分支 / 并入主干是**调用方**的动作，而那不是本函数的职责。

② 它与"已提交但未并入主树"【是两件事】，而后者本任务不做。
   那条要在【观察面】上做（src/tools.ts，域外）——
   ⚠️ 而它是那条让「先提交再交终态」结构上不可达的缺口。

③ ★★ 本任务【没有接线】。
   `worktreeBaselineFreshness` 目前在**生产里没有消费者** ——
   而往哪接（在成员被派发时？在交终态时？）是一个设计决定，
   它落在 `src/scheduler.ts` / `src/tools.ts`（都在 outOfScope）。
   ★ 本队那条纪律：**一个没有调用方的修法，与没有修法在观测上完全相同。**
   ⇒ 所以这一条被**写下来**，而不是让"函数存在"替它作证。

④ 主干引用按 main / origin/main / master / origin/master 依次取第一个读到的。
   ★ 一个都读不到 ⇒ `undecidable`（而不是"是最新的"）。
```

---

## 九、★ 一条与全文同源的话

本任务的全部内容是**一个字**：

> **差。**

而它一路展开成：一个方向（`HEAD..main` 而不是 `main..HEAD`）、
一个量（只数主干有的，不数自己的）、一个后果（你会读到已经不存在的缺口）。

★ 而它属于本队今晚归纳的那条：

> **一个写在某个时刻的事实，在没有被复核的情况下继续被当成本刻的事实。**

工作树的基线就是一个"某个时刻的事实" —— 而它此前从没被复核过。
