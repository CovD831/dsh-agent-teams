# task-atomicity：一条不可机械化的判据，留还是走（t75）

> **本文回答一个问题，而不是修一个判定。**
> 判据本体在 `src/gates/contract/task-atomicity.ts`，验证在
> `scripts/verify-task-atomicity.test.mjs`，形状臂在
> `scripts/gate-task-atomicity.test.mjs`。

---

## 1. 它是什么，以及它的缺陷

```
它判的：  path.trim().endsWith('/')            ← ★ 字符串的最后一个字符
它声称的：「失败能不能归因到一个原因」          ← 一个语义性质
```

### 1.1 ★★ 证伪它的一对（t43 构造，t75 复现）

```
['src/registry.ts', 'src/index.ts']           ⇒ ok
['src/registry.ts', 'src/index.ts', 'src/']   ⇒ blocked
```

★ **两边的工作完全相同** —— 只差一个字符，而裁决相反。
⇒ 它判的是**写法**，不是**工作**。

### 1.2 而 t43 的结论比"这个实现写错了"更强

> **「原子性」这个标准本身抗拒机械化。**

而 t38（作者）与 t43（验证者）从两个方向独立得出同一结论：

| 方向 | 结论 |
|---|---|
| t38（作者） | 这个信号在语料上零误报，但只有 **2 个正例** ⇒ 不敢接生产 |
| t43（验证者） | 即使它在语料上成立，它判的也是字符串末字符 |

⇒ ★ **两条独立路径指向同一件事**：不是"修一修就能用"，而是**它判不了它声称的那件事**。

## 2. ★★★ 决定：**留着，并改正它自己的声明**（选项 ①）

### 2.1 三个选项，各自为什么

| 选项 | 内容 | 为什么不选它 / 为什么选它 |
|---|---|---|
| ① | **留着 + 改正声明** | ★ **选中。** 理由见 §2.2 |
| ② | 移除 | ★ 会一起删掉两样**不是判据**的东西：**尾斜杠对照对**（一种可复用的证伪手法）与**"它刻意不在装配清单里"**那条臂（它记录的是**为什么生产没被改动**）。⇒ 而"删掉一条做不到的判据"的同时删掉"它为什么做不到的证据"，会让下一个想重建它的人从零开始。 |
| ③ | 留着 + 只收紧臂 4 的说明 | ★ **不够**：臂 4 的说明在**夹具**里，而**读的人不会打开夹具**。他读到的是 `description`（控制台渲染的那一句）。⇒ ③ 修的是"将来维护它的人"，而真正的缺口在"现在读它的人"。 |

### 2.2 ★ 为什么选 ①：那条声明**就是它全部的产出**

```
FACT 5  它【不接生产】（验证：不在 ALL_GATES；由臂 9 钉住）
FACT 6  ★ 它的消费者只有它自己那两个夹具
        ⇒ 那个"攒语料"的输出是【测试日志里的一行】，不是一份会被读的报告
```

★ 这两条合起来是一个很窄的结论：

> **它在当前形态下，对仓库的唯一影响就是：多一条要去维护的判据 ——
> 而那条判据的说明书写着它做不到的事。**

★ 而 `registry.ts:441` 明说 `description` 是 **"the console renders it"** ——
**给人看的那一句**。既然它不接生产，那句话就是它**全部的产出**；而那句话是假的。

⇒ 所以 ① 不是"给它一个体面的台阶"，而是**把它唯一的产出一词一句地改成真的**。

### 2.3 ★ 与今天那条纪律的关系

> **一句话里的每个数字 **和每个名词**，能不能指出它的来源？**（j-0007）

★ 这里"**原子性**"这个词的来源是 —— **没有**。
代码里没有任何东西在判它。

## 3. 改了什么（而**没有**改什么）

### 3.1 改了：两句给人看的声明

| 位置 | 改前 | 改后 |
|---|---|---|
| 文件头第一行 | 「判据：这个任务的契约够不够【原子】」 | 「判据：契约【声明面的形状】是不是**可能**不可归因 —— ★ 而不是"够不够原子"」 |
| `description` | 「……够不够原子……不原子时说清可以拆成什么」 | 「★ 它判的是【契约声明面的形状】，不是「原子性」本身……★ 而"形状看起来不原子"只是"失败可能不可归因"的一个【征兆】，不是它的判据（t43 已用"只差一个尾斜杠的同一件工作"证伪过那个更强的声称）……★ 本判据【不接生产】」 |

### 3.2 ★★ 没有改（而这几条是刻意的）

```
· 判定逻辑 —— 一个字没改（.endsWith('/') 原样）
  ★ 因为"修那个判定"这件事【做不到】（§1.2），而不是"不想做"
· 生产行为 —— 一个字没改（它仍然不在 ALL_GATES 里）
· 臂 1~9 —— 原样保留（它们记录的是这个信号的形状与边界）
```

★ 而这也是契约第 5 条（「本任务不改变任何生产行为」）的落实。

## 4. 反向半边：臂 10 与它的定向突变

### 4.1 臂 10（新增）：`description` 必须如实

```
断言 ①  不许出现承诺性措辞：/够不够原子/ · /是不是原子/ · /判断.{0,6}原子性/
断言 ②  ★ 反向半边：必须【说清它判的是什么】—— 不是把"原子"那些字删了了事
        ⇒ 必须出现 /形状/ 与 /征兆/，且必须写明 /不接生产/
```

★ 断言 ② 是防恒真的关键：**"删掉那句承诺"也能满足断言 ①**。
⇒ 所以要求它**同时**说清自己判什么、以及那个结论的强度。

### 4.2 定向突变（实测）

```
把 description 改回「够不够原子」那份原文
  ⇒ ★ 臂 10 单独红（其余 11 条绿）
  ⇒ 还原后 12/12 绿
```

## 5. 剩下什么没做（如实）

```
1. ★ 它仍然是一条【判不了它自己领域】的判据 —— 本任务只是让它的声明诚实，
   而没有（也无法）让它变得可机械化。
2. ★ "攒语料"这个理由我**存疑但没有否定**：
   它的输出目前只是测试日志里的一行（`ℹ 真实语料 N 条 ⇒ {...}`），
   而那是否算"被读到"，取决于有没有人真的去看那行。
   ⇒ 若将来有人把它接成一个真正的报告，这条判据的价值会变 —— 那时应当重估。
3. ★ 那条尾斜杠对照对**保留在 `verify-task-atomicity.test.mjs` 的臂 4**，
   而它是**可复用的证伪手法**：任何"靠字符串形状判语义"的判据都可以照它做一遍。
```

## 6. 一条留给下一个人的话

★ 本判据的作者（t38）在自己的文件头里写下了那条边界：

> 「一份『看起来能分开』的信号，可能只是**在两个样本上重合**。」

★ 而 t75 做的事，是把那句话**从注释搬到 `description` 里** ——
因为注释是给维护者看的，而 `description` 是给**读结论的人**看的。

⇒ 而这两拨人**不是同一拨**。一条只对前者诚实的判据，
对后者仍然是一句做不到的承诺。
