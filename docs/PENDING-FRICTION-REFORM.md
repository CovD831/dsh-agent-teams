## 0. 用户的原话（这份文件的全部依据）

> 「我们原本为什么会去做卡点？是因为在无人值守的开发中，有很多时候会停下来问人，
> 但其实很多停下来的卡点，都是可以自己去解决的。」

**⇒ 一句话：卡点 = 任务停下来了。经验 = 同一个坑被踩出来的次数。**

## 6. ★ 本轮（2026-10-08 unified-pipeline）长出来的三条可迁移经验

**它们不是这个计划的产物，而是这轮派工中由成员实测暴露出来的。记在这里因为它们该进判决台账。**

### 经验 A：一个数必须连同它的【测量装置】一起读

`pipeline-author` 在一轮内报了**四个** mutation score：

```
1.000  harness 用 indexOf 应用变异体（打到 L23 而非变异的行）+ 基线红
0.438  同一个坏 harness，基线绿
0.584  harness 修好（按 m.line 定位），基线绿
0.603  同上 + 新加 8 条臂                      ← 交付读数
```

★ **四个都是真的，只是各自属于不同的装置。**
把它们并排看会产出一个**从未发生过的趋势**（"改进了 37%"）。

⇒ **与 j-0007 同族**：一个写在某时刻的事实继续被当成本刻的事实 ——
只是这次被当成"趋势"的，是四个各自都正确的数。

**★ 判据**：报一个数时，若它的装置变过，必须**连装置一起报**，否则并把排就是伪造趋势。

### 经验 B：正向臂测不出"一律拒绝"

`pipeline-author` 的 `decomposeContract` 里那道自洽闸门**写反了**：

```js
if (outcome.status === 'decomposed') { …拒绝… }   ← 反了
⇒ 完全正常的拆解被判"形不一致" ⇒ 拆解永远不成功 ⇒ P3 落地后整个阶段不可用
```

**★ 而它是被一条【反向半边臂】抓出来的** —— 那条臂喂的是"合法的拆法必须被放行"。

⇒ **一般形式**：
> **正向臂只喂"该被拒"的输入，所以它测不出"一律拒绝"。**
> **一条判据要能被证伪，必须有一条臂喂【该被放行】的输入。**

★ 这是本队既有那条（*缺对照臂就无法区分「判据有效」与「判据在乱拒」*）的**产品级实例**：
它逮住的不是夹具问题，是一个**会让整个阶段无法交付**的缺陷。

### 经验 C：写域越界靠"记得带绝对路径"防不住

实测：`pipeline-author` 用 heredoc 追加文件时 cwd 是**会话工作区**而非它的 worktree
⇒ 误改了主树的 `scripts/friction-triage.test.mjs`（它自己发现、逐字比对、完全还原）。

⇒ **"下次记得带绝对路径"是一条靠记忆的规则，而本队已证明这类规则会腐烂。**
**该变成一条机械检查** —— 派工收口时核一次：`git status --short` 在主树上是否只有预期产物。

★ 而它是在**已经还原、git status 已干净、无人会发现**的情况下**自己报的** ——
那正是本队那条最贵纪律的主动形态。

### 经验 D：契约措辞的【方向】必须在契约里，不能只在执行者心里

★ **这是 captain 自己的错，而它造成的后果比前三条都大。**

原 t14 的 objective 写的是：

> 「…使 …`skippedAll` 在场时**报出「这一步没被检查」**，而不是抛出一句空的 `rejected: `」

**⇒ 这句话没说清第三支该【放行】还是【拒绝】—— 它只说了要"报出"。**
而最自然的读法就是"把空串填上内容、**仍然拒绝**"。**执行者正是那样实现的，字面完全正确。**

**而权威口径在 `src/tools/delivery.ts:118-122`**（t64 已修的同一形态实例）：

```js
const notChecked = evaluation.ok === false && evaluation.skippedAll !== undefined
if (notChecked) {
  ctx.logger.warn(`… was NOT checked — allowing it through, because "not checked" is not "refused"`)
}
if (!notChecked && (evaluation.ok === false || …)) { …拒绝… }
```

⇒ **放行 + 留痕，不是拒绝 + 说清理由。**

**★★ 判据（本队该记的一条）**：

> **一个"加第三个分支"的契约，必须写明那个分支的【出口方向】（放行 / 拒绝 / 阻塞），
>   否则执行者会按最自然的读法填 —— 而"最自然的读法"通常在语义上是反的。**

★ 而它之所以危险：执行者做出了字面正确、夹具全绿、定向突变能红的交付 ——
**四条证据都指向"成功"，而方向是反的。**

★ 发现的路径也值得记：执行者**不是在契约里看出来的**，是**去读主树那个同类实例的提交信息**
（`t64`: *"A safety constraint that does not fire must not refuse everything;
it must let the step through and leave a trace that it was never checked."*）才查出来的。

⇒ **同一条形态的既有已修实例，是方向问题唯一可靠的判据来源。**
契约写"照 X 的口径做"时，**必须指名 X**。

### 经验 E：worktree 的 base 可能不是 HEAD，而它的后果是【整棵树】

实测（2026-10-08）：

```
task-t1  的 base = ba32130  2026-10-08 12:25   ← 主树 HEAD
task-t13 的 base = ad7a3ed  2026-10-06 21:25   ← ★ 两天前
task-t14 的 base = ad7a3ed  2026-10-06 21:25   ← ★ 两天前
```

而两天里 `src/` 发生过拆分（`src/tools/` 是拆出来的）。

**⇒ 后果不是"少了一个文件"，是【整棵树的语义不同】。**

- t14 报"契约里的路径不存在"（**对它的树成立，对主树不成立**）
- t14 一度说"注册表口径与报告不一致"（**因为它那棵树早于 t58**）
- ★ 而最贵的：**它按那棵树的语义设计了修复方向，而那方向在主树上是反的**

**⇒ 判据**：
> **一个 worktree 的 base 必须可读、且与被测对象一致；不一致时，
>  它的全部结论（包括"缺陷在哪"）都要重新核对，而不只是"补一个文件"。**

★ 本队已有两条同族记录：`j-0010` ①（宿主持旧模块）、`t80`（45/46 个 worktree 落后）。
**这次是第三条：base 旧了两天，而没人知道。**

### 经验 F：★「动作发生了」与「事实建立了」不同形 —— 只有后者可测

**这是 2026-10-08 那一夜最贵的一条，而它被四条独立的处置各证否一次：**

| # | 处置 | 谁提的 | 实测 |
|---|---|---|---|
| ① | 「跑 `pnpm build` 就能消掉 stale」 | captain | ✗ 盘上对齐 ≠ 进程内对齐（`LOADED_STAMP` 是加载时的缓存常量）|
| ② | 「重派就会写入 `baseRevision`」 | decompose-author | ✗ attempt 4→5→6 均 `None` |
| ③ | 「重建 worktree 会触发 `onWorktree`」 | decompose-author | ✗ **回收 ≠ 重建**；回收不触发回调 |
| ④ | 「手工 `git worktree add` 也会建树」 | captain（当场撤销）| ✗ 手工 add **绕过调度器** ⇒ 回调不调用 ⇒ 仍不写 |

**★ 四条错法逐字相同**：

> **把「一个会写东西的动作」当成了「那个东西已经写了」，**
> **而没去读那个东西到底写没写。**

**⇒ 一般形式**：

> **「动作发生了」与「事实建立了」在读数上不同形 —— 而只有后者可测。**
> **⇒ 每一次「这样就该好了」都必须配一个【读回那个事实】的动作，
>   否则它只是一个关于动作的猜想。**

★ 而它比本队既有的那条（*"没测到" ≠ "测得是零"*）**更进一步**：
  那条说的是**读数**要分三态；**这条说的是「同一个动作之后，事实有没有被建立」也要分。**

**★ 而它最值钱的形态是【拒绝给它一个新方案】：**
`decompose-author` 在连证否自己两条处置后写道：

> 「这一轮我**没有**再给你一个新的『应该能行』的方案。
>   因为我已连续两次把『会写的动作』当成『写了』——**第三次我不猜了**：
>   剩下那两条我标的是 `unmeasured`，不是 `it works`。」

⇒ **宁可控着，也不让台账记下一个不成立的结论。** 这是这条经验的主动形态。
