```

⇒ 所以这不是"判据坏了"，是"**没有人把值交给它**"
```

## 三、★★★ 为什么没有更早发现 —— 本任务的核心回答

那 14 条红里，**7 条是真的行为回退**，而其余是"夹具在旧位置找已搬走的东西"。
⇒ ★ **两者在失败清单里同形** —— 清单只报"红"，不报"**红在哪一格上**"。

### 怎么让两者不同形

```
· 「读错位置」 = 那个东西【不存在于】它该在的地方
                 ⇒ 读数是"此处没有"
· 「行为回退」 = 那个东西【存在于】它该在的地方，而【没人用它】
                 ⇒ 读数是"此处有，而入口为空"
```

★ 而分栏就是让这两句话**各有各的字段**：

| 栏 | 问句 | 读数是 |
|---|---|---|
| 目标集合内 | 搬运前有的符号，搬完还在吗 | `shrunk`（附**哪一个、从几变几**） |
| 目标集合外 | 它在别处还在吗 | `outside` —— 在 ⇒ **搬走了**；不在 ⇒ **坏了** |

⇒ ★ 缺了"外面那一栏"，就只能说"少了"，而说不出"搬走了"还是"坏了"。

★ 而那正是 t94 那条判据（`scripts/gate-pure-move.test.mjs`）的形状 ——
本任务独立复核了它的判定逻辑（臂 2/3/4/5 全绿）。

## 四、★★★ 一个本任务实测出来的【度量的盲点】

`gate-pure-move` 的 `symbolCounts` 会**剥掉注释与字符串**（那是对的：
注释里的符号名不是引用）。而这一条带来一个后果：

```
skippedAll 在 t69 的修复里出现在【模板字面量】内部：

    `update_task rejected: ${dispatchGates.skippedAll ?? `…no reason…`}`

⇒ 它被 strip() 正确地移除了 ⇒ **代码级计数 = 0**，而【修复之前也是 0】
```

**MEASURED（本任务实测）**：

```
                代码级（strip 后）   原文（含注释/字符串）
  pre（拆分前）        2                  16
  t70（拆分后）        0                   0
  now（本修法）        0                   3
```

⇒ ★ **这条判据看不到 `skippedAll`** —— 不是因为它坏了，是因为那个符号
**在代码里的位置就在字符串里**，而 strip 抹掉字符串是对的行为。

★ 而这正是本队记账的「**守卫检查了另一个同名的东西**」的又一种长相：
度量读的是"剥掉字符串之后的那个名字"，而被测的东西住在字符串里。

⇒ ★ 所以本任务把 `skippedAll` 那一格的验证改成**功能性**的（见第五节），
而不是靠计数 —— 因为**计数在这一个符号上恒为 0**。
