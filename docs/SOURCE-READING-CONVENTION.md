# 读源码文本的夹具：统一口径（t87）

**判据**：`scripts/gate-source-reading-convention.test.mjs`（6 条臂）
**它防的是**：「同一个修复第二次发生」。

---

## §1 为什么要有这条判据（两次实测）

```
· t39  拆 tools.ts     ⇒ 15 个夹具在旧位置找已搬走的东西（★ 那次 captain 手动修的）
· t70  拆 update-task  ⇒  8 个夹具在旧位置找（18 条红）
★ 而两次的修法【相同】：改用 scripts/tools-source.mjs 的 toolsSource()
  （它是 src/tools/** 的递归 —— 所以它自动涵盖 update-task/）
```

### ★★ 而真正的问题是：**为什么第一次修完之后，第二次还会发生？**

```
⇒ 因为第一次修的是【那 15 个夹具】，而【不是那个约定本身】。
  「读源码文本时要用统一口径」这句话【没有被任何东西强制】——
  它是一条靠人记得执行的约定，而本项目的文档已经反复证明这类约定会腐烂。
```

⇒ 所以本判据的产出不是"又修了几个夹具"，而是**把那个约定变成机制**。
**它的价值就在 §4 那次全仓普查的数字里。**

---

## §2 核心问句（这条判据全部精度的来源）

> **那个夹具读这个文件，是为了【从它的文本里找某个东西】，还是为了【它本身】？**

| | 该怎么做 | 例子 |
|---|---|---|
| **为了文本里的东西** | 走统一口径 | 「生产的代码里有没有 `gitChangedPaths: observed?.paths`」—— 那件事的落点**会随重构移动**，夹具不该关心它在哪个文件 |
| **为了它本身** | 直接读 | 数据表（`kind-requirements.json`）、"那个文件存在吗"、逐文件普查、拆分布局本身 |

★ 这条问句把一个看着主观的分类变成了**可机械判定的**：
`readFileSync` 的结果**被用来做什么**，在源码里读得出来。

---

## §3 三态（互不同形）

```
declared-exception  —— 白名单里、且【带理由】的直接读
hardcoded           —— 写死了 src/tools/** 下某个具体文件去找文本 ⇒ **该改**
unreadable          —— 范围外（临时检出 join(repo/ws, 'src', …)）⇒ 不判缺陷
```

★ 第三态**必须真的有人落**（本仓有夹具自己造临时仓库）——
否则"范围外"会被静默并进"写死路径"，而那是**误伤**。

## §4 ★★ 全仓普查（本任务先跑一次，如实报）

```
ℹ t87 普查：全仓夹具共 17 处读本仓 `src/**`
    白名单（有理由的直接读）13 · **该走统一口径的可疑处 2** · （临时检出，范围外）2
  ✗ 可疑：scripts/gate-changed-paths-message.test.mjs:398  join('src', 'tools/update-task.ts')
  ✗ 可疑：scripts/gate-restart-arbitration.test.mjs:533    join('src', 'tools/status.ts')
```

### ★★★ 而那 2 处里的第一处，**此刻就是坏的** —— 这是第三次

```
gate-changed-paths-message.test.mjs:398 读 src/tools/update-task.ts，
  断言 /gitChangedPaths:\s*observed\?\.paths/
而那段代码【已经】搬到了 src/tools/update-task/dispatch.ts
  ⇒ 那一臂现在就是红的（实测：该夹具 6 pass / 1 fail）
```

⇒ **本判据第一次运行就抓到了第三次**（前两次是 t39 / t70）。它证明自己不是恒真的。

★ 而那 2 处**不在本任务的 inScope 内**（本任务只写"判据 + 文档"两个文件），
所以判据**如实报红**，把处置交给持有那些夹具写域的人。
**一个为了让自己的任务变绿而放宽这一条的实现，会把本判据最值钱的那个读数抹掉。**

## §5 三次我自己踩到的错（都记下来，因为它们是同一类错的三个面）

| # | 错法 | 形态 |
|---|---|---|
| ① | 白名单按**文件**给，于是 `gate-changed-paths-message` 整份免检，而它内部有一处**已经断了** | **一个文件的整体属性，替它内部的一行作了证**（与"守卫检查了另一个同名的东西"同族） |
| ② | 反向半边按**文件名**禁，把那条**合法**的豁免（读某条判据自己的措辞）也一起禁了 | **它按"哪个文件"禁，而规则是"哪条路径"** —— 同一个形态的镜像 |
| ③ | 第一版把"该文件已引统一口径"当成整份豁免 | 同上：整体属性替局部作证 |

⇒ 三次的共同形态：**判定落在了比规则更大的单位上**（文件 > 行）。
而它的危险一致：**把一处真实的断裂藏在一个"看起来守规矩"的文件里**。

## §6 定向突变

```
把一处走统一口径的读改回写死路径（加一行 readFileSync(join(ROOT,'src','tools','status.ts'))）
  ⇒ 普查的可疑处 2 → 3，且新的一处被【逐条点名】
  ⇒ **臂 1 红**
还原后：可疑处回到 2、MUTANT 计数 0、臂 5 仍绿（逐条点名）
```

## §7 已知边界（写出来，不假装覆盖）

- 只认**同一行**内的 `readFileSync(join(ROOT, 'src', …))` 形状。跨行调用需要解析器，
  而一个会被字符串字面量骗到的解析器比"少扫一条"更坏。
- 白名单是**逐处**（`file:路径尾巴`）给的，且每条理由必须指名它属于哪一类豁免
  （数据表 / 拆分布局本身 / 逐文件普查 / 判据自己的措辞 / 统一口径的定义处）。
  ⇒ 臂 4 逐条核对，且**反向**禁止把 `src/tools/**` 的文本读放进白名单
  （三个正当例外各自写明了理由）。
- 临时检出（夹具 `mkdtemp` 出来的仓库）不在范围内 —— 它们不是本仓的源码面。
