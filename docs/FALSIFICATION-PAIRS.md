# j-0002：同一件工作的两种写法必须同裁（对照对）

**判据**：`scripts/gate-falsification-pairs.test.mjs`（5 条臂）
**形状**：它不是**一个**判据，而是一条**通用夹具形状** ——
对每一条判据，构造「同一件工作的两种写法」的对照对，断言两者**同裁**。

---

## §1 它防的是什么

```
task-atomicity（已退役）断言「inScope 里有目录条目 ⇒ 会新建目录 ⇒ 不原子」，
而它的实现只做 path.trim().endsWith('/')。⇒ 实测：

  ['src/registry.ts', 'src/index.ts']          ⇒ ok
  ['src/registry.ts', 'src/index.ts', 'src/']  ⇒ blocked

★ 而那两边做的是【同一件事】（都在 src/ 下干活）。
⇒ 即：那个判据判的不是「工作」，而是「**写法**」。
```

---

## §2 哪一半可机械化、哪一半不可（这决定了它的形状）

| | 可机械化？ | 说明 |
|---|---|---|
| **同裁断言** | ✅ 是 | 跑两次、比裁决 |
| **构造哪一对** | ❌ 否 | 它需要理解那个判据**在判什么** |

⇒ 所以形状是：**通用夹具 + 每条判据手工提供一对**（清单内联在判据文件里，见 §5）。

---

## §3 ★★ 三态（不得合并）

```
same               —— 同裁 ⇒ 合格
diverges           —— 不同裁 ⇒ ★ 判据判的是写法（**这是要报的缺陷**）
cannot-construct   —— 无法构造对照对 ⇒ ★ **必须附理由**（而不是悄悄跳过）
```

★ 而 `cannot-construct` 的理由必须**实质**（判据断言 > 30 字）：
它要说清**为什么这条判据的输入里不存在"同一件工作的两种写法"这回事**，
而不是"我们没做"。

---

## §4 ★★★ 全仓普查（本任务先跑一次，如实报）

```
[j-0002 普查] 注册表 11 条判据
    —— 有对照对 1 · 无法构造（附理由）10 · ★ 两者皆无 0
[j-0002 对照] 2 条对照对全部同裁
```

★ **"两者皆无 0"** 是这一臂守的纪律：既没有对照对、也没有理由的判据
就是**被静默跳过的**，而"静默跳过"与"这个判据没问题"在读数上同形。

★ 而「有对照对 1」指的是 **`dispatch.changed-paths`**（两条 pair，见下）。
其余 10 条各有一条实质理由 —— 典型三类：

| 类别 | 例子 | 为什么构造不出 |
|---|---|---|
| 输入是**枚举值**，不是工作的描述 | `runtime.liveness`（事件名） | 一个事件要么是这个字符串、要么是别的 |
| 输入是**状态**，不是工作 | `delivery.convergence`（收敛态） | 同一种状态只有一种写法 |
| 要求**真的跑测试 / 真的执行命令** | `completion.mutation` / `backtest` / `r5` / `verify-rerun` | "两种写法"要成立得先让两边产生同一批变异体 / 同一批被选中的测试 ⇒ 那要先构造等价的代码树 |

---

## §5 ★★ 数据为什么**内联**在判据文件里（而不是一个 JSON）

```
t77 曾把两个清单放在 scripts/fixtures/falsification-pairs.json 里。
★ 而那份 JSON【从未被提交】（全仓 untracked）⇒ 于是它**腐烂了**：
  两条 pair 都指向一条**早已退役**的判据（contract.task-atomicity），
  而那条让本判据的三个臂长期红着，报的却是一句"它可能被改名或删除了"。
```

⇒ 本版把数据**内联**：一个判据的数据与它的判据放在一起，
它们会**一起**被 commit、一起被看、一起腐烂（如果会的话）。
★ 这不是"省一个文件"，而是把**两份真相**合成一份。

★ 而臂 5 把"清单与注册表必须对得上"变成**显式**断言：
任何 pair 或 reason 指向不存在的判据 ⇒ 立刻红，且红里说清**是哪些**。

---

## §6 ★★★ 两个"恒真"陷阱（本任务实测抓出来的，都写进代码注释了）

### ① 对照对的数据**从来没有到达判据**

```
第一版：baseContext 把 extra 在**顶层**展开，而对照对的数据是嵌在 update 里的
  ⇒ `...extra` 把 update 整块**覆盖**成默认值
  ⇒ 两次求值喂的是**同一份默认输入** ⇒ 当然"同裁" ⇒ 臂 1 **恒真**

★ 而它**只在定向突变下才现形**：我把 changed-paths 改成"按写法判"，臂 1 **仍然绿**。
```

### ② 两端都 `unmeasured` **不算同裁**

```
`unmeasured` 是"没能测量"，而"两边都没能测量"与"两边测了、结论相同"是**两件事**。
★ 把它算成同裁，会让这条判据在**任何未接线的判据上都"通过"**。
⇒ 臂 1 现在显式断言"两端都必须有实质裁决"，并把这一条写进理由。
```

---

## §7 定向突变（真的跑）

```
把 src/gates/dispatch/changed-paths.ts 改成【按写法判】：
    const normalized = path.startsWith('./') ? path : normalizeWorkspacePath(path)
  ⇒ **臂 1 红**，且它报出的正是那一句：
       dispatch.changed-paths: 写法 A ⇒ ok ｜ 写法 B ⇒ blocked
         而两边是同一件工作：两边申报的是【同一条路径】…
★ 还原后：5/5 绿、MUTANT 计数 0。
★ 而这个突变同时是 §6① 的**检出器**：第一版夹具在它之下**照绿不误**。
```

---

## §8 已知边界（写出来，不假装覆盖）

- **构造哪一对**不可机械化 —— 所以清单是**手工**的，而它会随判据退役而腐烂
  （§5 的臂 5 是那条的守卫，但它只能发现"指向了不存在的判据"，
  发现不了"这条判据变了、所以这一对不再是同一件工作"）。
- 判据只覆盖**"同一件工作的两种写法"**这一种对照。
  ★ "状态枚举"、"等价代码树"是**另外两种**对照形状，各有各的夹具。
- 本判据**不修**它发现的缺陷（那是写域问题）：若某条判据真的"判的是写法"，
  它**如实报出来**，而不是顺手去改那条判据。
  ★ 理由：顺手改的东西，会盖住另一件事的报告（今晚三次事故的教训）。
