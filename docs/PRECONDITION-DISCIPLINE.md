```
★ 队长说:「共同点是——一个先决条件失败，而后续断言照跑了」
```

## 2. ★★★ 它收紧了一层（★ 而这层才是要害）

```
★★ 「真正的危害不是"断言照跑了"，而是——
    【它跑出了结果，而那个结果看着像真的】」

· cd 失败 ⇒ 后续命令在【另一个目录】跑，却输出了一个像样的答案
· 文件是空的 ⇒ 输出 0，而 0 是个合法读数
⇒ ★★ 所以判据不是"有没有报错"，
   而是【这一条读数会不会因为我没检查先决条件而变假】
```

### ★★ 它的实例（本会话实测）

```
它第一条命令:cd <t104> 2>/dev/null && git merge-base --is-ancestor 71790be HEAD
⇒ ★ `cd` 失败被 2>/dev/null【吞掉】⇒ 后续在【队长工作区】跑
⇒ 报 NOT ancestor
★★★ 而真相是在队长工作区里 IS ancestor ✅
⇒ ★★ 关键:「NOT ancestor」【不是报错，是一个看起来完全正常的检查结果】
```

```
★★ 若会 ⇒ ★ 先检查;★ 而检查失败时【不输出】
```

### ★★ 本会话的三次实例（同一形态，三个不同外在）

| # | 外在 | 而真相 |
|---|---|---|
| **①** | `for f in …; do git show "HEAD:$f" > "$f"; done` ⇒ 文件被截断成 0 字节 | ★「命令失败」与「文件是空的」是同一个结果 |
| **②** | `git show "HEAD:$f"` 指向**早于该任务提交**的 HEAD ⇒ 用旧版覆盖新版 | ★ 而 `git show` **成功了** ⇒ 比 ① 更隐蔽 |
| **③** | `cd <不存在的目录> 2>/dev/null && …` ⇒ 检查在**别的目录**跑了 | ★ 而它输出了「NOT ancestor」⇒ **一个看起来正常的结论** |

⇒ ★★★ **三次的外在都不同,而共同点是同一条:【失败没有传播到读数上】。**
