# 层次之间不得吞掉结论（S2）

> **这份文件是一条【判据】的说明书** —— 判据本体在
> `scripts/gate-layer-verdict.test.mjs`，本文说清它判什么、为什么这么判、
> 以及它的边界在哪。
>
> ★ 而它**不碰 `src/` 与 `lib/`**：它把一条**已经存在**的约定
> （`registry.ts` 的三态合并规则）固化成可执行的断言，而不是重新实现它。

---

## 1. 它防的是什么失效（MEASURED，t58 实测）

```
判据层报 unmeasured（"我没能测量"）
    ↓
而位置级【把那个结论吞掉了】：
    appliesTo 返回 false ⇒ 那条判据不进 gate()
    ⇒ 位置级看到的是"几条判据都 skipped"
    ⇒ ★ 它报 ok
```

**后果**：**5 个 kind 的完工位置永远报 ok** —— 而那 5 类占真实任务的
**29%（15/51）**。

★ 形状：**「没检查」与「检查了而通过」在位置级读数里同形。**

而它正是本仓反复记账的那条：

> **一个机制在它没想到的场景里，给出一个看起来正常的答案。**

★ 在这里，"正常"是**字面的** —— 位置级报的就是 `ok: true`。

---

## 2. 它断言的是一条【函数关系】，不是一个具体值

契约原话：

> 给出同一组判据裁决，位置级必须给出同一个结论（不许用别的信号覆盖它）。

⇒ 判据里有一份 `expected()`，它**只看判据层的裁决**；
而断言写成 `position === expected(gateVerdicts)`。

```
判据层（evaluated 的那些）            →  位置级应当给出的结论
─────────────────────────────────────────────────────────────────────
（无判据）                                ok: true   · skippedAll 缺席
（有判据、而 evaluated = 0）              ok: FALSE  · skippedAll 在场   ← t58 修的那一格
任一 unmeasured                          ok: false  · unmeasured 在场
否则任一 blocked                         ok: false  · blockers 在场
其余                                     ok: true
```

★ 于是"位置级用别的信号覆盖了结论"会在这里红 ——
因为那个覆盖会让它**偏离 `expected()`**。

### 2.1 ★ 为什么要单独测"函数性"（同输入同输出）

只测"它落在 `expected` 上"是不够的：一个内部依赖**顺序 / 时间 / 全局状态**的实现
可能每次都恰好落在 `expected` 上 —— 而那不是函数关系，是巧合。

⇒ 臂 4 对每种输入跑**两次**（各自新建注册表、各自新建探针对象），断言逐字段相同。

★ 为什么必须**新建两个实例**：同一个实例跑两次会共享内部状态，
而那恰好会把"跨调用污染"伪装成"函数性"。

## 3. ★★★ 三态与那条例外（本判据最容易做错的地方）

```
┌ 空位置（registered === 0）          ok: true   · skippedAll 缺席   ← ★ 正常
├ 全跳过（registered > 0, eval === 0）ok: FALSE  · skippedAll 在场   ← t58 修的那个
└ 判据报 unmeasured（eval >= 1）       ok: false  · unmeasured 在场   ← 判据层的结论
```

**`registry.ts:692` 写明了空位置为什么必须是 `ok`**：

> 空位置是正常情形，不是异常 —— 在那里产出这段话，会让每个还没接判据的位置
> 都读起来像出了问题，而那正是「把正常读成异常」，
> 与「把异常读成正常」一样有害。

### 3.1 所以本判据**不能**写成"位置级 = 判据层的最坏态"

那句话在**空位置**上不成立。

按用户 2026-10-08 的标准（「特定条件下起效的也能加，只是需要把那些特定条件
顺便加上去」），那条例外被**写进判据本身**（`expected()` 的第一个分支），
而不是断言一个更大的、会误伤空位置的东西。

### 3.2 ★ 两条反向臂，各自守住一端

```
臂 2（吞掉臂）  判据说"没能测量" / "全跳过" ⇒ 位置级【绝不许】是 ok
               ⇒ 防"该拒的不拒"
臂 3（反向臂）  空位置 / 全通过 / 部分跳过+通过 ⇒ 必须【仍然】是 ok
               ⇒ 防"该放的不放"（过度修正）
```

★ 两条**合起来**才排除掉两个常量实现（全 ok / 全非 ok）。

## 4. 定向突变：两个方向，而它们的失败签名【不同】

| 突变 | 内容 | 结果 |
|---|---|---|
| **A'** | `allSkipped` 那一支改成 `ok: true`（＝无条件 ok） | 臂 **1 / 2 / 5** 红 · 臂 **3 绿** |
| **B** | `allSkippedVerdict` 的条件去掉 `registered > 0`（＝过度修正，空位置也非 ok） | 臂 **1 / 3 / 5** 红 · 臂 **2 绿** |

★★ 两个突变的**失败签名不同** ⇒ 两组臂各自独立地测了不同的东西，
而没有一组是"全红或全绿"的装饰。

★ 而 A 的第一版我写错过（我只改了 `unmeasured` 与 `blockers` 两条返回，
漏了那个**专门的 `allSkippedVerdict` 分支**）—— 结果是 **5/5 全绿**，
而当时被读成"突变没打红"。⇒ 修法：先确认突变【真的落到了构建产物上】
（读一次 `lib/`），再跑臂。**"突变没生效"与"臂是恒真的"在症状上同形。**

## 5. 它与别的判据的分工（不重复）

| 判据 | 判什么 | 层次 |
|---|---|---|
| `gate-registry.test.mjs` | 注册表自身的形状（register / list / 重复 id …） | **单层** |
| `verify-input-requires.test.mjs` | 输入面**接没接上**（`requires` 的 B 层 + A 层） | **一格** |
| **本判据** | **两层之间的接缝**：判据层的裁决能不能被位置级如实读出 | **接缝** |

★ 而它与"输入面核对"是**两个不同的问题**：
输入面问"这条判据要的那一格接没接上"，本判据问
"**它说完话之后，上一层有没有如实复述**"。

---

## 6. 已知边界（不假装它能做更多）

1. **它判的是"接缝的性质"，不是"每条判据都正确"** ——
   一条判据自己算错了、而位置级如实复述了那个错误，本判据**不会**报。
   （那是那条判据自己的夹具的事。）
2. **它用探针判据，不读那 11 条真实判据** ——
   而这是刻意的：真实判据的适用条件会随任务类型变化，
   把它们的当下分布写成断言，就是把「当前形状」写成不变量。
   ★ 而"真实判据在真实 ctx 上会说什么"由它们的**各自夹具**回答。
3. **`skippedAll` 与 `unmeasured` 的措辞**不在本判据的范围内 ——
   本判据只要求它们**不同形**（在场 / 缺席），不评判它们写得好不好。
4. **它不覆盖"位置级之间"的层次**（例如 runtime 位置的特殊纪律）——
   那是 `runtime` 自己的契约（`docs/GATE-REGISTRY.md` §5）。
