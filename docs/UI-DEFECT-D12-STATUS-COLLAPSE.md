# UI 缺陷 D12：主行把「干完了在等」与「还没开始」画成同一行

> **用户 2026-10-15 实测发现**（截图 + 原话）：
> 「像现在这也是个问题，按理来说一个成员就是一条并行分支，但是我目前看成员的 ui 面板，
>  我看到一个在跑，其他几个全是等待队长派工，
>  所以目前的 ui 状态更新不及时，或者说**状态显示不够清晰合理**」

★ **队长的核实结论：不是"更新不及时"** —— 面板显示的数据**是对的**
（4 个成员名下**确实**没有未终结任务）。问题是**它把两种不同的状态画成了同一行**。

★★★ **关键对照就在用户那张截图里**：

- `ui-dissect`：**完成 12 · 失败 3** ⇒「等待队长派工」

⇒ **一个刚生成、没干过活的成员，和一个刚做完 12 件任务的成员，主行完全一样。**

## 2. 根因（`src/client/MemberRow.tsx:153-172`）

```ts
export function memberDoingText(member, current, owned, t): string {
  if (current !== undefined) { ... }                     // ① 有当前任务 ⇒ 显示它
  if (member.activity === 'working') return ...          // ② 否则看 activity
  const open = owned.filter(t => 未终结)                  // ③ 否则找未终结任务
  if (open.length > 0) return ...                        //    ★ 报一个它并不在做的 id
  return t('member.status.waitingAssignment')            // ④ ★ 落到「等待队长派工」
}
```

**第 ④ 行把四种不同的情形合并了**：

| 真实情形 | 该显示 | 现在显示 |
|---|---|---|
| **刚做完 N 件，在等下一件** | 「**已完成 t68，待派工**」 | 「等待队长派工」 |
| **生成后从未干过活** | 「**从未派工**」 | 「等待队长派工」 |
| **上一次失败，在等重派** | 「**t67 失败，待重派**」 | 「等待队长派工」 |
| **被停用/归档** | 「已归档」 | 「等待队长派工」 |

⇒ ★★ **四种情形压成一行，而那正是本仓记账最久的形态**：
> **「没找到」与「确实没有」同形。**

★ 而**讽刺的是**：`MemberRow.tsx:146` 的注释**恰恰在讲这条纪律**：
> 「Every branch says *something*: a member with no current task reads "等待队长派工"
>  rather than an empty line, because **"this cell has nothing" and "this member has
>  nothing to do" must not look the same**.」

⇒ **作者防住了"空 vs 非空"，但没有防住"干完了 vs 没开始"。**

## 3. ★ 与用户原话的关系

> 「按理来说**一个成员就是一条并行分支**」

★ 用户的心智模型是：**每个成员 = 一条独立的进度线**。
而现在的面板**只在"正在跑"时有信息量**，其余时候**所有分支都塌缩成同一行**。

⇒ ★★ **所以问题不是"状态更新慢"，是"状态空间被压扁了"** ——
面板在**静息态**（没有任务在跑）几乎不携带信息，**而静息态恰恰是大部分时间**。

---

## 4. ★★ 修法（与 B 线的 S2/S3 同一条路）

**输入已经有了**：`owned`（该成员全部任务）+ `round`（轮次）+ 任务的 `status`。
⇒ **不需要新数据出口，只需要把第 ④ 行拆开。**

```
if (有未终结任务)      → 显示它（现有行为）
else if (有过失败且最新是失败) → 「t67 失败 · 待重派」   ★ 新增
else if (有已完成任务)  → 「已完成 t68 · 待派工」        ★ 新增
else                  → 「从未派工」                    ★ 新增（与上面不同形）
```

★ **而"待派工"必须与"从未派工"不同形** —— 因为：
- 前者：**队长欠它一个任务**（该派了）
- 后者：**它还没参与过**（可能正常，也可能配置错了）

⇒ 两者**处置相反**，而**现在同形**。
