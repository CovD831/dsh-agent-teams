# 判断 → 行动：卡点与判决的分诊器

> **这份文件回答一个问题：那些已经记录下来的卡点与判决，其中哪些现在就该派任务去做。**
>
> 用户的原话（它存在的理由）：
>
> > 「经验记录下来后，应该自动判断是否要去派任务去做 ——
> >   不管是卡点还是经验，我们不是都已经构建过了吗。」
>
> `node scripts/friction-triage.mjs` ⇒ 一份 JSON（给机器）+ 一份人话清单（给 captain）。

---

## 一、它为什么存在：链条上唯一缺的那一环

```
卡点 ⇒ 自动记录        ✓ t22
判决 ⇒ 有格式有读者    ✓ t57
判决 ⇒ 可机械化判断    ✓ t65
★ 判断 ⇒ 行动          ✗ ← 本工具
```

★ 本队对这件事有一条归纳，正对着最后那一行：

> **「一个没有调用方的判断，与没有判断在观测上完全相同。」**

前三级都建好了，而**没有任何东西把第三级的结论变成一件可派的活** ——
于是它在观测上与"从来没有判断过"一样。

---

## 二、它产出**提案**，不建任务

建任务 / 派工是 **captain 的判断**（协议所限：成员不建任务、不派活）。
⇒ 本工具只回答「**该派哪几条、以及为什么**」，并把那个消费做**便宜**：

```sh
node scripts/friction-triage.mjs                 # 人话清单
node scripts/friction-triage.mjs --json          # 机器可读
node scripts/friction-triage.mjs \
  --frictions <dir> --judgements <dir>           # 输入由调用方给（默认 .agent-teams/…）
```

## 三、三个动作（★ 而它们的补救动作不同）

| 动作 | 含义 | captain 要做的 |
|---|---|---|
| `to-dispatch` | 值得派，且现在就能派（写域空闲） | 建任务、派出去 |
| `blocked` | 值得派，而**被写域挡着** | 先看**是谁挡的**，再决定排队还是拆 |
| `no-action` | 不需要行动（已修 / 已裁定不修 / 已排期） | 什么都不做 |

★ **`blocked` 必须说出「被谁挡」** —— 只说"被挡住了"等于让人自己去翻，
而那正是本工具要消掉的那件事。

### ★★ 而"被谁挡"里有一处最容易被读错，所以它单独成字段

实测（第一次对真实台账跑）：11 条判决里 **8 条判 `gate`**，而它们的写域**都是**
`['scripts/', 'src/gates/']` ⇒ **7 条互相挡**，`blockedBy` 全部写着同一个 id。

**那技术上是对的**（它们确实都在同一区域），而它**读起来是错的**：
"被 X 挡"暗示 X 是那 7 条的**前置条件** —— 而它们只是**同区域的一批候选**，
顺序**可以随便排**。⇒ 所以每一条 `blocked` 都带一个 `blockedKind`：

```
mutual     被【清单之外】的东西占着（一个正在跑的成员、一个已派的任务）
           ⇒ 那是真的前置：那件事做完之前不该动这些文件
same-area  与本清单里更早的一条同区域
           ⇒ 串行是为了让合并简单，不是因为前置 —— 谁先谁后都可以
```

★ 而"顺序可互换"**不是猜测**：判据的产地是 `scripts/gate-*.test.mjs`，
**一条判据一个文件** ⇒ 两条判据天然不共享文件。

## 四、★ 写域为什么是「粗」的（以及为什么不去猜细的）

每一条判据提案的写域都是 `['scripts/', 'src/gates/']`。

★ 我一开始想给每条判决推一个**具体文件**，好让冲突检测更精确。**做不到**：
判决的 `claim` 是**人话散文**，它推不出可靠的文件路径。
实测（11 条判决）：只有 2 条的正文里出现 `scripts/`，而其中一条指的是
**它讲的两次事故**，不是它自己要产出的文件。

★★ 而硬推一个"具体文件"会让提案**声称**一个它没有依据的写域 ——
那比"粗的写域"坏得多：

```
粗的写域    ⇒ 一条提案多等一会儿（代价可接受）
编的写域    ⇒ 两条真的冲突的提案**同时被派出去**（代价是返工）
```

⇒ 所以提案里同时带一格 `scopeBasis`，把"为什么是粗的"**随提案一起交出去**，
不让它看起来像是已定的。

## 五、★ 卡点的第四态：**没有 `resolution` 记录 ≠ 待办**

判据（顺序即优先级）：

```
fixed           ⇒ no-action     已修。★ 再派一次的代价不是零：
                                台账里会多一条"同一个卡点被修了两次"，而它读起来像"这个卡点很顽固"
wontfix         ⇒ no-action     已裁定不修（那是一个决定，不是待办）
scheduled       ⇒ no-action     已排进某个任务
open            ⇒ candidate     真的还欠一个动作
auto-recorded   ⇒ ★ 不要求回填  判据拒绝那一下**自动记的**（t91 加；见下）
（没写、且非自动）⇒ unknown     ★ 第四态：**台账需要回填**
```

### ★★★ t91 之前，那第四态里混着两类东西

实测（t91，当前台账 203 条）：

```
自动记录的拒绝（判据拒绝那一下记的）   167 条   ← ★ 它们没有 state 是设计如此
人记的、而没有 state                     9 条   ← ★ 真的需要人看
────────────────────────────────────────────────
合成一格时报出来的数字                  176     ← ★ 一个误导的数字
```

★ 而那是本队那条纪律的又一实例：**一个读数把两类东西算成同一类** ——
「**不需要回填**」与「**还没回填**」在它眼里同形，而两者的补救动作**相反**：
前者什么都不用做，后者要人去补一个 `state`。

⇒ 修法两步：

```
① recordFriction 在【自动记录】时写下 `auto: { tool, point, gate? }`
   ★ 由**调用方声明**，不由 recordFriction 猜 —— 猜错的方向是单向的：
     它会把人工记录算成"不需要回填"（那正是本任务要消掉的误导，只是反了过来）
   ★ 缺省 = 人工记录 ⇒ 一个"忘了声明"的自动条目会落回待回填（**显眼**），
     不会伪装成"不需要人管"（**隐形**）。错的那一侧选可见的那一侧。
② 分诊器据此把它分出去，单列一格
```

### ★★ 而它有一条**明写的**向后兼容回退，且那个存量可见

`auto` 是本轮才加的字段，而台账里现存的 167 条自动记录**写于它之前** ⇒
只看新字段，这个修复对**已有台账**完全无效（数字仍是 176）。

⇒ 所以有一条回退：老记录的 `title` 以 `<tool> rejected` 开头
（实测分布：`update_task` 160 条 + `create_task` 7 条，全部由拒绝路径写下）。

★★ **而它是一条代理读数**（j-0003：代理读数在它所代理的东西没变时也会变）——
代理是 title 的**字符串前缀**，被代理的是"这条记录是谁产生的"。
⇒ 所以命中的条目带一格 `via: 'title-fallback'`，而报告里印出**还有多少条在吃回退**：

```
★ 其中 167 条是靠 **title 前缀**认出来的（它们写于 auto 字段之前）——
  那个数字降到 0 时，那段回退就可以删了
```

★ 而它**不与真字段合流**：`auto` 在场时优先用它；回退只在**没有** `auto` 时生效
⇒ 一个新记录绝不会被标题前缀误判。

### ★ 而"自动条目"的内容一个字都没少

本任务是**加一格**（`auto`），**没有**动 `resolution` / `message` / `context`：
自动条目**仍然**带 `resolution`（"当时还没修"是事实），只是那个 `resolution` 没有 `state` ——
而分诊器现在**看得懂这个缺省**。⇒ 它们仍能在 HTML 里读、仍能被判据扫。

#### ★★★ 派工建议必须带【可核的理由】

「不给理由的建议，与一条『请自己挑』在观测上同形。」

```
   ★ 那是"专长匹配"的可核形式 —— 它与**角色标签**不同形：角色是声明，写域是做过的事

```

实测（当前台账）：


所以这条建议只是"谁现在空闲"，不是"谁擅长它"」。
★ 一个"总能挑出一个人"的实现看起来更好用，而它在没人匹配时**会撒谎**。

```

```

**把基础设施工况伪装成关于数据的结论。**

### ★★★ t97：审查前移到**生成的那一刻**

用户原话（这一节存在的理由）：

> 「我觉得可能不用等到要派的时候再去做任务的对抗性审查，在自动生成的时候就可以去做了。
>   生成完的任务，可以带一个『已审查』的字段。
>   因为有的任务是自动生成的，有的任务是需要问过我之后再生成、再派发的。

⇒ 核心是一条**路由规则**，而字段就是判据：

```

不带          ⇒ ★ 必须先审一遍才能派
★ 而"不带"**不是错误** —— 它是"这条路没走自动生成"的正常状态
```

## 六、判决那一侧的四个取值（★ 与 t65 同一口径）

```
gate         可机械化 ⇒ 产出一条待建任务提案

discipline   表达不出断言 ⇒ 不产出提案
```

### ★★ 一处**明写的重复**，以及它的到期条件

`judgement-triage.mjs`（t65 的交付）**不在本仓库里** —— 那次交付报了 failed 且未提交。

★ 而那个重复**是明写的**：两边的取值集合与同口径在源码里并排列着，

"判据边界上的分歧，不是谁算错了"。拿它当对齐样本会测到一条两边都不同意的。

## 八、怎么读它的输出

```
卡点 203 条 · 判决 13 条
⇒ 待派 1 · 被写域挡 7 · 无需行动 27
   ★ 台账待回填 9（人记的、而没有 state —— 这些**真的需要人看**）
   · 自动记录 167（判据拒绝的那一下记的，★ **不要求人回填**）
     ★ 其中 167 条是靠 **title 前缀**认出来的（它们写于 auto 字段之前）——
       那个数字降到 0 时，那段回退就可以删了

── 自动记录（167）：判据拒绝那一下记的，★ **不要求人回填** ──
  · completion.backtest：41 条
  · …
```

★ **每一格各自要人做不同的事**（派 / 排队 / 什么都不做 / 回填台账 / **什么都不用做**）——
所以它们**分开计数**。一句"总计 N 条"读不出该做什么。

★★ 而"台账待回填 **9**"与"自动记录 **167**"**必须分开印**：
合成一格时报出 176，而其中 165 条**根本不需要人来管** ——
★ 一个数字把两类东西算成同一类，而读的人会照着它去补 176 个 `state`。

★ 而自动那一格**不逐条列**（167 条会把清单淹掉）：给计数 + 按判据的分布。
那让读的人知道"这些是自动的"，而不是"这些是我欠的"。

## 九、一条留给下一手的提醒

夹具里的 `freshTool` 用 cache-busting 重新 import —— 而它**只在单模块时够用**。

★ 本工具今天只 import `node:` 内置，所以单个 bust 是够的。
**一旦有人往里加本地 import，那个 bust 就必须跟着改**，否则突变会静默地测旧代码，
而报告会读作"突变没打红"（方向恰好相反）。

⇒ 这条前提**已经被写成可执行的断言**（夹具里那条"本工具是单模块"的自检）。
