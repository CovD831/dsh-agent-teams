# 判决 → 判据：自动分类器

> **这份文件说的是一件事：那三处判断现在由一条可执行的规则给出，而不是由人写。**
>
> 用户的原话（这是它存在的全部理由）：
>
> > 「是否该记录为可沉淀的经验这点需要做自动判断，而不是交给我，
> >   然后哪些经验能自动去做成判据也得自动化。」
>
> 在它之前，那三处判断**全部靠人写**：判决 JSON + 一张提案表。
> 现在跑 `node scripts/judgement-triage.mjs` 就有读数。

---

## 一、它判什么

输入是一份判决候选：

```json
{ "id": "j-00XX", "claim": "……", "scene": { … }, "counterexample": "……" }
```

★ **它只读 `claim`。** `scene` 与 `counterexample` 不进判定 ——
本文件末尾那节"它不做什么"会解释为什么那是刻意的。

输出是**四态**：

| 裁决 | 含义 | 人接着做什么 |
|---|---|---|
| `gate` | 可机械化 —— 能写成一条对某个输入返回真/假的断言，而它读的东西现成可取 | 照 `where` 说的形状造出来 |
| `diagnosis` | 只能诊断 —— 它需要"理解任务在做什么" | 标记给人看，**不拦** |
| `discipline` | 表达不出断言 | 只写进纪律文档 |
| `unmeasured` | ★ **判不了** | 先把 claim 改清楚 |

---

## 二、三处判断，各自的判据

### ① 值不值得记成判决 —— 它能不能被写成一条断言？

「能写成断言」在文本上就是**"有一个可检查的联结结构"**：

```
「…没变时也会变」            ⇒ 条件 + 后果
「…一样，下一次才分岔」        ⇒ 对比 + 时点
「要打在 A 上，不要打在 B 上」  ⇒ 二选一
「只在…时才…」                ⇒ 条件 + 后果
「取决于…是不是…」            ⇒ 依赖 + 判定
「当…被改动了，…就是…」        ⇒ 条件 + 后果
```

★ 而 **`j-0001`「停在可恢复的中间态」让掉线无害** 恰好**没有**这个结构：
它说的是"无害"，而"无害"不是一个读数 —— 检查什么？没有输入。
⇒ 它落 `discipline`。

**这一格改了三版，每一版都被 9 条真实语料打回**（值得记下来）：

| 版本 | 做法 | 实测结果 |
|---|---|---|
| 1 | 认"泛名词"（判据/代价/状态…）作可指向的对象 | **9 条全过** ⇒ 恒真（连 j-0001 也过） |
| 2 | 认"文件名/标识符"作可指向的对象 | **9 条全否** ⇒ 恒假 |
| 3 | 认**可检查的联结结构** | 8 条过、j-0001 落 discipline ✅ |

★ 版 1 与版 2 是同一格的两个极端，而它们都**看起来在工作** ——
这正是"一条恒真的断言会在突变全红的表象下活下来"那条记账的又一次发作。

### ② 能不能机械化 —— 那条断言读的东西是不是现成可取的？

判定顺序是**从窄到宽**，而且每一步都有理由：

```
① 需要"理解任务在做什么"        ⇒ semantic    ⇒ diagnosis
②' 约束的是【夹具怎么写】        ⇒ runtime-ctx ⇒ fixture-helper（不是判据）
② 别的机制有没有把它【送过来】   ⇒ injected-…  ⇒ gate
③ git 读数                      ⇒ git         ⇒ gate
③ 注册表读数                     ⇒ registry    ⇒ gate
③ 文件系统                       ⇒ filesystem ⇒ gate
③ 源码文本                       ⇒ source-text ⇒ gate
④ 没看出来它读什么              ⇒ undefined   ⇒ unmeasured（★ 第四态）
```

★ `②'` **必须排在 `②` 之前**：`夹具`/`针脚`/`断言` 一出现，这条 claim 就是
"关于测试怎么写"的，而不是"关于产品做什么"的。放在后面会让 `j-0005`
被归到"注入"那一类，而它的正确形状是**夹具辅助**。

★ `①` 必须**最先**：一条 claim 可以同时提到文件和"理解"，而那时正确答案是后者。

### ③ 做成什么形状 —— 由【输入的种类】决定

| 输入的种类 | 形状 | 落在哪 |
|---|---|---|
| 源码文本 | 判据 | `scripts/gate-*.test.mjs` |
| 文件系统 | 判据 | 扫盘的判据 |
| git | 判据 | 建任务时 / 收口时的检查 |
| 注册表读数 | 判据 | 读结构化读数的判据 |
| **别的机制送来的东西** | 判据 | 判据的输入面（`requires`） |
| **运行时的 ctx** | ★ **夹具辅助** | 夹具辅助库（**不是判据**） |

★★ 最后一行是**关键的一格**：它与"判据"一样是**可机械化的**，但**产物不同** ——
它约束的是夹具的写法，不是产品代码。一条"夹具写错了"的判据会拦下
**正确的产品代码**。⇒ 合成一个会让下一个人去注册表里找一个**不在那里**的东西。

## 三、与那张手写表的比对（★ 两者都要能被质疑）

```
$ node scripts/judgement-triage.mjs --compare
…
Against the hand-written table: 7 agree, 1 disagree, 1 uncomparable
```

### 那一条**真的**不一致（j-0003）

```
工具：gate      —— 这条断言读的东西是现成可取的（夹具里的距离/行号/缩进）
表：  diagnosis —— 判"只能诊断"，因为【找出哪个读数是代理】需要理解
```

★ 两边说的**不是同一件事**：
· 工具回答"这条断言**一旦写出来**，读的东西现成可取吗" ⇒ 是
· 表回答"**构造这条断言**（挑出那些读数）需要理解吗" ⇒ 需要

⇒ 这是**判据边界**上的分歧（"可机械化的判据是窄的"），不是谁算错了。
★ 而本工具**不替它改判**：改判会让"两者都要能被质疑"变成"工具向表看齐" ——
那时表就成了真值，而它明明只是人的判断。

### 那一条**表里没有**（j-0009）

```
j-0009: uncomparable —— the hand-written table does not list this judgement
```

`docs/JUDGEMENTS-TO-GATES.md` 写于 2026-10-07、列 8 条；j-0009 产生于 10-08 00:25。
★ 而**不**给它补一行、让它落 `uncomparable`，是刻意的：补一行会让"表当初判过它"
这个**假事实**成立。
★ 而它同时是**那张表自己的过期读数** —— 正是 j-0007 说的那件事
（写在某时刻的事实继续被当成本刻的事实）在**这张表自己**身上发作。

## 四、★★★★ 它自己的适用范围（★ 特定条件一起写上）

用户的标准：

> 「也不是说在特定条件下起效的就不能加，只是需要把这些特定条件顺便加上去。」

⇒ **它只在这些前提下给出三态**：

```
① claim 必须【已经是一句可检验的陈述】。
   没有 claim / 太短 ⇒ unmeasured。★ 本工具**不替人把 claim 改写清楚** ——
   它只回答"这一句能不能判"，不回答"它应该是什么意思"。

② 它判的是 claim 的【形态】，不是它的【真伪】。
   一条形态上可机械化的判决，仍然可能是**错的**。

③ 它**不读语义**。所以"需要一个模型来理解"的断言只能落 diagnosis。
   ★ 那是**判据本身的边界**，不是本工具的缺陷。

④ 它**不读 .agent-teams/**。判决来源由 `--judgements <dir>` 传入 ⇒
   它可以在别的仓库里跑。
```

★ 而**每个裁决**都带 `conditions`：那是从 claim **自己写下的限定语**
（"只在…"、"对…成立"、"若…"）里读出来的 —— **不是**本工具替它编一句免责声明。
claim 没写限定语时它**如实返回空数组**：那是"读到的"事实，不是"我们假设它通用"。

## 五、它**不**做什么（与"它做什么"同样重要）

```
✗ 不判 claim 的真伪 —— 它只看形态（见 §四②）
✗ 不把含糊的 claim 改写成清楚的 —— 它落 unmeasured，把问题交回去
✗ 不自己读 .agent-teams/ —— 目录由调用方给（§四④）
✗ 不改那张手写表 —— 表在 docs/ 里，归它的作者；本工具只读它、并如实报出分歧
✗ 不把"与表不一致"当失败 —— 退出码只反映"工具跑没跑成"。
  ★ 把分歧当 exit=1 会让 CI 在**工具是对的、表是错的**时也红，
    而那时正确的动作是**去看那一条**，不是"修到两边一样"。
```

## 六、抄来的语料会腐烂 —— 所以有一条对拍

本工具的 9 条 claim 是**从 `.agent-teams/judgements/*.json` 抄来**的
（因为它的写域不碰 `.agent-teams/`）。⇒ 而"抄来的东西会腐烂"正是本队的记账
（j-0004 / j-0007 说的都是这件事）。

⇒ 所以 `--judgements <dir>` 会**对拍**，而它的三态不同形：

```
match       —— 抄的是当前那一份
stale       —— 分叉了，并**列出**哪些 id 不同
unmeasured  —— 读不到目录（★ 不是 match：见 §七）
```

---

## 七、三处"不同形"（本库的纪律，逐条落在这里）

```
① 四态互不合并
   "判不了"(unmeasured) 与 "判了：只能诊断"(diagnosis) 不同形 ——
   前者要你去改 claim，后者要你接受它不拦。合成一个会让"我读不懂"
   伪装成"一条关于这条判决的结论"。

② 读不到 ≠ 空的
   readJudgements(不存在的目录) ⇒ undefined（"我没能读"）
   readJudgements(空目录)       ⇒ []        （"读了、一条都没有"）

③ 形状上可分辨，不是靠读理由
   gate ⇒ 有 where（要造出来的产物位置）
   diagnosis ⇒ 有 where，而**内容不同形**（"标记给人看，不拦"）
   unmeasured ⇒ **没有 shape**
```

★ 第 ③ 条在本任务里**改过一次**：第一版断言"diagnosis 没有 where"，
实测当场红 —— 两者**都有** where，而**内容不同**才是要钉的东西。

## 八、怎么跑

```sh
node scripts/judgement-triage.mjs                      # 内置 9 条，出人话报告
node scripts/judgement-triage.mjs --compare            # 附带与手写表的逐条比对
node scripts/judgement-triage.mjs --json               # 机器可读
node scripts/judgement-triage.mjs --judgements <dir>   # 跑一个判决目录（并对拍）
node --test scripts/judgement-triage.test.mjs          # 夹具
AGENT_TEAMS_TRIAGE_MUTATION=1 node --test scripts/judgement-triage.test.mjs   # 含定向突变
```

## 九、一条留给下一手的提醒

夹具里的 `freshTool` 用 cache-busting 重新 import —— 而它**只在单模块时够用**。

★ 本工具今天只 import `node:fs` / `node:path`，所以单个 bust 是够的。
**一旦有人往里加本地 import，那个 bust 就必须跟着改**，否则突变会静默地测旧代码，
而报告会读作"突变没打红"（方向恰好相反）。

⇒ 这条前提**已经被写成可执行的断言**（夹具里那条"本工具是单模块"的自检）：
一旦有人加了本地 import，它会当场红，而不是等到某次突变"莫名其妙不打红"。
